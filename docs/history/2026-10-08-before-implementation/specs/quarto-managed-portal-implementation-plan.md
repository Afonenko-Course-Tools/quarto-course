## Авторизация и цель

Продолжение согласованного общего плана §10/§17 после прямого «Приступай к реализации». Тематические draft PR, без merge/release и изменений реальных курсов. ## Архитектура

Новый opt-in `project-publish.portal: index.qmd` выбирает один root QMD → index.html, несовместим с home. Effective outer `project.render` пуст. Для этого режима native `project.output-dir` декларативно находится внутри `.project-publish/native`; конечный каталог задаёт `project-publish.output-dir`, например `_site-student`. Hook не меняет авторские YAML/output-dir/type. Stock Quarto очищает native output до pre-hook: backup из pre-hook не обеспечивает сохранность предыдущего выпуска.

Public output сохраняется до commit. Root render остаётся только private outer shell. Publisher создаёт принадлежащий попытке native selection profile до beforeRender, проверяет effective selection штатным inspect и замораживает control bytes; оригинальные config bytes сохраняются. Audience profiles контекста прежние, дополнительный profile предназначен только portal child. Собственный profile с таким именем, альтернативным .yaml или группой/included configuration не получает молчаливого переопределения.

Workspace разделяет nativeOutput и конечный output, portal input. BuildState содержит actual attempt-owned portal input/output/renderProfiles/control hash. BeforeRenderContext раскрывает portal selection для adapter checks. Integration.metadata получает отдельный portal RenderContext без выдуманного member namespace; member namespace/format/output сохраняют прежний смысл. Root QRC namespace задаёт сам QRC config. Portal child использует snapshot и собственный attempt output; PROJECT_PUBLISH_MEMBER предотвращает рекурсию coordinator. Никаких дополнительных generic phases/registry/callback.

Publish начинает stage только с текущего portal output, размещает members, затем прежние ordered finalizers и commit. При отказе finalizer public не меняется. При отказе stage→output после backup прежний public восстанавливается. Failed cleanup не удаляет восстановленный/прежний public в managed mode. Ownership/state drift проверяются до любых разрушительных операций. Результаты другого профиля сохраняются.

Документированный `entrypoints/render.ts` принимает только поддержанный выбор profiles и проверяет managed config до запуска stock Quarto. CLI --output-dir отвергается wrapper до native cleanup. Обычный `quarto render` без output override с декларативным private output допустим; сторонний прямой вызов stock Quarto с публичным --output-dir не покрывается гарантиями hooks. Preview использует безопасный путь и сохраняет последний успешный снимок.

Первоначальный portal consumer — нейтральная HTML navigation/QRC страница. Реальные QRC captures, final targets/search, ресурсы и закрытые ссылки проверяются на actual child output. Новые claims production pedagogical body/неизвестные carriers/полный P2 не добавляются.
