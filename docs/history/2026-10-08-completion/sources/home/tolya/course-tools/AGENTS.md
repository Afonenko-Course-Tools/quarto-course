# Инструкции для Codex

Сначала прочитать [START-CODEX.md](START-CODEX.md). Действующие решения следующего
внедрения находятся у владельца Core:
[контракт](quarto-course/spec/authoring-model-next.md) и
[линейный план](quarto-course/docs/plans/2026-10-08-course-tools-implementation.md).
Задачи других владельцев связаны из START. Корневые старые specs/планы/evidence
используются как история, не заменяют актуальные прямые указания пользователя.

Этот каталог не Git-репозиторий. Не создавать дополнительный репозиторий;
сохранять нужную ещё не закоммиченную историю и изменения в существующих
репозиториях владельцев до очистки. Сохранять пользовательские рабочие деревья.

Перед изменением поведения сверить актуальную архитектуру и необходимые узкие
рефакторинги. Нативные публичные API Quarto, однократная миграция, согласованные
код/spec/README/примеры, минимум надстройки без нового общего runtime.

Финал реализации включает новые выпуски инструментов, публикацию документации
штатно в `gh-pages`, обновление существующего OPEN PR Cybersecurity и очистку
LOCAL/REMOTE веток только инструментов/шаблона. Сохранить main, служебную gh-pages
и ветки открытых автоматических GitHub PR; теги/Releases не удалять.
На исполнение 9 часов от начала; использовать доступные ресурсы ноутбука.
Проверять локально, CI на финальных этапах. Реализация/тесты — medium;
спецификации, README, docs, инструкции, шаблон и его проекты — ultra,
если исполнитель позволяет настройку reasoning.
Вопросы по новому серьёзному расхождению показывать обычным текстом с примерами
и вариантами; согласованные вопросы заново не открывать.
