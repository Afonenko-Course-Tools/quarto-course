# Конечные решения по аудиту тестов Core

Реестр закрывает 112 строк содержательного аудита от 9 ноября 2026 года.
Исторический аудит остаётся основанием, а не очередью обязательного удаления
33 файлов. Единица решения — защищаемая граница и уникальные assertions.
Принятые false-PASS, source rewriting, orphan runtime tests и удаление test-only
facade повторно не объявляются новой реализацией этой кампании.

Сохранённые сценарии сохраняют свои assertions у названного получателя — того
же файла. Предложенное объединение отклонено там, где отдельный дешёвый boundary
control полезен: объединение файлов само по себе не улучшает наблюдаемое
поведение. Для трёх уже снятых suites указан конкретный получатель. Нет
оставшихся строк «объединить позже» и искусственной нормы удаления тестов.

Новые различающие уточнения этой кампании: exact role diagnostics,
сравнение всех затронутых Navigation outputs при отказе, сохранение QRC-owned
probes, empty-output no-op и различающиеся source/output resource bytes.
Manual transport сохраняется: внешний consumer audit не даёт основания
совместимо снять документированный маршрут. Native manual assignment/Body без
PL теперь проверяет отдельная actual min/current matrix.

Browser/print scenarios сохраняются с разными обещаниями: интерактивность,
print-media, реальный PDF/text и совместная Presentation+Navigation имеют
разные consumers. Их дальнейшее уменьшение не является условием закрытия.
Полный Java/SP course census и released/installed composition не подменяются
единичными native fixtures; они остаются отдельной приёмкой интегратора.
