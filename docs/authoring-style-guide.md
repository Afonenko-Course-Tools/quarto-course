# Руководство по авторской записи курса

Обычный документ остаётся документом Quarto: Markdown, include, native
упражнения, формулы, ссылки, вычисления, cache/freeze и Reveal не требуют
платформы оценивания. Core добавляет учебные метаданные, выбранный состав
работы и проверенный экспорт. Точный контракт: [учебные элементы](../spec/learning-elements.md),
[видимость](../spec/visibility.md), [представление](presentation.md),
[Body экспорт](body-export.md).

## Структура курса и владельцы

Логический корень задаёт `course.id` один раз для экспортных ключей.
Теория, задачник, справочник, лекционные и практические слайды могут быть
отдельными native Quarto-проектами. Их `_quarto.yml`, списки входных файлов и форматы,
namespace каталога и выходные пути остаются собственными. Корневой портал
перечисляет входы явно; Publisher при необходимости компонует текущие результаты.
Банк для выбранного экспорта передаётся `--book`, работа — `--work`.

QRC связывает адреса разных проектов. Оно не переносит чужие тела задач.
Обычные местные include организуют текст внутри native проекта. Не копируйте
условие задачника на слайд ради ссылки: у слайда собственный ID и ссылка к
владельцу канонической задачи. ID задачи устойчив внутри выбранного банка;
папка, номер слайда, размещение результата и namespace QRC не заменяют course.id.

## Файлы, темы и ресурсы

Используйте содержательные латинские имена со словами через дефис (`checksums.qmd`,
`exr-checksum`) и русские отображаемые заголовки. `index.qmd` — входная
страница проекта. Нативные `_quarto.yml` и `_metadata.yml` сохраняют свои имена.
Страница `checksums.qmd` может иметь соседний `checksums/` с её ресурсами;
общие изображения помещайте в явно выделенный общий каталог. Папка ресурсов
нужна лишь при наличии ресурсов. Группы файлов отражают смысл, а native
`book.chapters` определяет порядок и навигацию книги.

Явный `sec-*` полезен для устойчивой ссылки на тему, но не обязателен для
каждой задачи. Ресурсы проекта перечисляйте с привязкой к корню, например
`resources: ["./assets/**"]`, и проверяйте фактический `quarto inspect .` и
список фактических результатов. Копирование ресурсов и публичный ZIP — явные отдельные
действия. Отсутствие ссылки в меню или запись `.gitignore` не ограничивает
native копирование. Сгенерированный и закрытый экспорт храните в `_generated`,
исключённом из публикационных ресурсов.

## Задача и необязательные подсказки читателю

````qmd
## Контрольные суммы {#sec-checksums}

:::: {#exr-checksum course-role="discussion" difficulty="intermediate" time="5" work-mode="pair"}
Предскажите, как изменится контрольная сумма после перестановки байтов.

::: {#sol-checksum}
Разберите исходные предпосылки и граничные случаи.
:::
::::
````

Идентификаторы `exr/exm/sol` нативные. Обычная задача может состоять только
из условия внутри `::: {#exr-id}`. `course-role`, `difficulty`, `time`,
`work-mode`, `target`, `project` и окружающий заголовок не обязательны.
Если метаданные указаны, их значения проверяются. Назначения:
`demonstration`, `discussion`, `independent-study`, `control`; сложности:
`introductory`, `intermediate`, `advanced`.

Используйте `exm-*` для собственного учебного примера. Решение `sol-*` может
быть самостоятельным native элементом. Связь сохраняется при вложении в
задачу/пример, явном `for="exr-id"` и однозначной существующей паре по суффиксу.
Суффикс не создаёт обязательную пару. Явная ошибочная цель отклоняется.
`.prerequisites` и `.reading` сохраняют штатные ссылки; они не назначают
оценивание. Core не наследует сложность или время от окружающей темы.

## Работы и раздатки

```qmd
---
title: Лабораторная работа «Контрольные суммы»
assessment:
  id: checksum-lab
  kind: lab
---

# Контрольные суммы

Краткие опорные тезисы и обычные ссылки на подготовку.

::: {.task-items}
1. @exr-checksum
2. [@exr-collision]{requirement="optional"}
:::
```

Один `.task-items` явно выбирает местные задачи в указанном порядке.
`assessment.id` может быть любым устойчивым lowercase ID работы; если
отсутствует, берётся native chapter-id или ID первого заголовка. Виды:
`lab`, `test`, `exam`, `handout`. Без metadata/kind получается неоцениваемая
раздатка. Для lab/test/exam задача по умолчанию обязательна; optional на Span
ссылки относится к включению в конкретную работу. В другой работе то же
задание может иметь другой статус. Раздатка не требует обязательности.

Повторная задача, несколько списков, неверный requirement и отсутствующий
выбранный член — ошибки. Обычная ссылка вне task-items не назначает задачу.
Старые `.assessment-items` и `.print-items` не поддерживаются.
QRC-ссылка не включается в местный состав и не импортирует условие.

## Ответы и выбранная платформа

Условие не содержит ключей и преподавательских заметок. `.grading-notes`
внутри задачи хранит критерии отдельно. Single-choice задаётся `.answer`
с единственным `.correct` вариантом; numeric/manual/multipart/matching —
YAML `.answer-spec` по [схеме](../_extensions/course-core/body-export/answer.cue).
Банк относится к одной задаче/примеру и не вложен в решение или notes.
Все ключи проверяются до публикационной проекции, даже в скрытой ветви.

Явный `target` нужен выбранному адаптеру; без него Core не изобретает manual
привязку. Для target-задачи используйте ведущий Header. Доставка на платформу,
баллы, попытки, проверяющая программа и внешние ID принадлежат выбранной интеграции.
Обычная книга не требует Moodle/PrairieLearn/Cloud. Поле `project` нужно,
только если выбранный адаптер использует локальный программный проект.
Публичные стартовые файлы и закрытые тесты должны иметь явные отдельные пути.

## Аудитории, HTML и слайды

Student/full — штатные профили с отдельными output-dir и `course.view`.
Student книги удаляет ключи, `.correct`, grading-notes и закрытые решения
обычных задач; публичные решения демонстраций/примеров сохраняются.
Без выбранной аудитории native документ сохраняет решения. Reveal сохраняет
авторские решения и использует штатные `.fragment` и `.notes`.
HTML оформляет вложенные ответы раскрываемо; настройка полного вида
описана в [Presentation](presentation.md).

Control не является автоматическим условием скрытия. Автор исключает целые
контрольные страницы из student `book.chapters`/списков рендера и включает в full.
Штатное условное содержимое записывается так:

```qmd
::: {.content-visible when-profile="full"}
Дополнительный преподавательский материал.
:::
```

Не используйте `.when-full` или `.unless-student`. Сложные форматные/metadata
условия принадлежат Quarto. Функциональные профили остаются активными вместе
с одной аудиторией. Открытый Git содержит исходники независимо от output.

Слайды имеют краткое собственное изложение и ссылки на полную книгу.
Для нативной Reveal-фрагментации используйте `.fragment` и `fragment-index`;
для заметок докладчика — `.notes`. Презентационные режимы и навигация описаны
в [Presentation](presentation.md). Проверяйте фактический HTML, маршрут под
URL-префиксом, заметки, поиск и PDF/печать. Штатные действия книги с репозиторием и штатный нижний колонтитул
Reveal используют явные обычные ссылки; точный source-map include не обещан.

## Выбранный экспорт

Из логического корня:

```sh
quarto run _extensions/course-core/entrypoints/export.ts \
  --book tasks --work checksum-lab \
  --output _generated/exports/checksum-lab.json \
  --profile java
```

Используйте установленный путь, включая владельца GitHub, если Quarto его
создал. Export выполняет один штатный исходный JSON-проход выбранного банка:
include, вычисления и функциональные профили сохраняются, полный HTML не готовится.
Включаются полные исходники банка, в том числе control вне списков глав.
Сначала выбирается одна работа, затем проверяются возможности выбранных тел.
Неподдержанное неиспользуемое задание не ломает выбранный экспорт.

Закрытый пакет содержит ключи/решения отдельно; соседний `.public.json`
содержит только условия и публичные поля ответа. Потребитель явно выбирает
пакет. Print получает условия и области ответа; Moodle/PrairieLearn проверяют
собственные типы. Неподдерживаемый выбранный узел или неразрешённая ссылка QRC приводят к ошибке;
универсальная переносимость произвольного Quarto/Pandoc не заявляется.
Публичные ресурсные пакеты исключают служебные исходники, скрытые ресурсы и
закрытые области проектов. Нативный AST и байты внутри своего корня определяют состав.

## Проверка авторской правки

```sh
quarto inspect .
quarto render index.qmd --profile student
quarto preview --profile student
quarto render --profile full
```

Для фактов полного запуска подключите лёгкие Core pre/post hooks и
используйте [native run API](native-run.md). Они не делают второй render.
Успешные текущие факты и exit 0 нужны для выпуска; retained файл после ошибки
не подтверждает текущий успех. Выбранный экспорт проверяйте локально до
интеграции с платформой. Import/load и student-view реальной платформы —
её отдельная проверка, не следствие валидного JSON.

Нормативные источники Quarto: [профили](https://quarto.org/docs/projects/profiles.html),
[условное содержимое](https://quarto.org/docs/authoring/conditional.html),
[штатные перекрёстные ссылки](https://quarto.org/docs/authoring/cross-references.html),
[Reveal](https://quarto.org/docs/presentations/revealjs/),
[фрагменты](https://quarto.org/docs/presentations/revealjs/advanced.html#fragments),
[заметки докладчика и печать](https://quarto.org/docs/presentations/revealjs/presenting.html).

При исходном экспорте audience-условие на целой задаче/работе и её внешних
контейнерах не исключает объект из выбора. Условия внутри задачи продолжают
отделять публичное условие от материала только для full. Функциональные профили
сохраняются. Это относится к служебному исходному проходу, а не к публикации HTML.
