# Исходный экспорт выбранной работы в Body

Публичные condition и publicAnswer не содержат contextual Download-ссылок
с marker-классом `project-download` (legacy `project-download-link`): Core удаляет
их до сбора ресурсного inventory. ZIP комплекта зависит от audience страницы и
не является публичным вложением LMS-вопроса; существующий teacher full ZIP также
не копируется в public package. Обычные немаркированные файлы, изображения и ссылки
сохраняются с действующими resource guards. HTML-render страницы по-прежнему
содержит contextual Download; это правило относится только к Body/package.

Запускайте команду из логического корня курса. В его `_quarto.yml`
`course.id` объявляется один раз. Выбранный банк — самостоятельный native-проект
`project.type: book` с фильтром Core. Канонические задачи объявляются только в
области `exercise-bank: true`; сама опция `--book` банк не включает. Файл работы
с `.task-items` может находиться вне области задач в том же native проекте.
Банк может содержать неподдерживаемые или платформенные задания, которые
не входят в выбранную работу.

~~~sh
quarto run _extensions/course-core/entrypoints/export.ts \
  --book tasks --work checksum-lab \
  --output _generated/exports/checksum-lab.json
~~~

Укажите фактически установленный путь Core, включая каталог владельца, если он
есть. `--book .` допустим, когда логический корень сам является банком.
`--profile java,review` выбирает дополнительные функциональные профили Quarto;
student/full здесь не передаются. CLI требует один банк, одну работу и путь
`.json`; создаёт родительские каталоги, закрытый пакет и соседний `.public.json`.
Экспорт сохраняйте в исключённом служебном каталоге. Закрытый пакет предназначен
явно выбранному потребителю и не является ресурсом публикации.

## Native-сбор данных

~~~ts
import { collectExport } from "./_extensions/course-core/body-export/collect.ts";
import { buildBodies } from "./_extensions/course-core/body-export/producer.ts";

const selected = await collectExport(courseRoot, {
  book: "tasks", work: "checksum-lab", profiles: ["java"],
});
const { package: teacherPackage, publicPackage } = await buildBodies(selected.result, {
  projectRoot: selected.projectRoot,
  courseId: selected.courseId,
  work: selected.work,
  includeClosed: true,
});
~~~

`collectExport` возвращает `{result: ReleaseResult, projectRoot, courseId, work}`.
Quarto выполняет один исходный проход JSON writer с include, вычислениями и
функциональными профилями. Временный профиль включает полные исходники и
обработчики Core, заменяет веб-обработчики, сохраняет штатное разрешение фильтров
и удаляется после успеха или отказа. Постоянная конфигурация не изменяется.
Core сохраняет фактический AST и независимую публичную проекцию в служебном
контейнере; обе проходят один native writer и разрешение shortcodes. Коллектор
читает готовые native JSON AST вместе с effective metadata; штатный Quarto
разрешает crossref. Полный HTML книги не готовится.

После разделения condition/publicAnswer производитель передаёт только выбранный
публичные condition и publicAnswer единым документом штатному `quarto pandoc --from=json --to=json --citeproc`.
Из native metadata с рабочим каталогом документа передаются только citation
inputs: bibliography, CSL, link-citations, lang/locale, references и
citation-abbreviations. Abstract и прочие поля документа не участвуют; citation
узлы в самих citation metadata отклоняются.
`nocite` не добавляет нецитируемые источники. Pandoc самостоятельно оформляет
цитаты и создаёт общую библиографию вопроса с единой нумерацией. Только после успешного citeproc
Core заменяет `Cite` его готовым содержимым. Каждому citation ID должна
соответствовать запись отдельного native citeproc witness, состоящего только
из фактических citation узлов вопроса без авторских bibliography блоков, иначе `BODY.CITATION_UNRESOLVED`, даже
если Pandoc вернул success с предупреждением. Приватные решения, заметки и
неназначенные вопросы не участвуют в публичной библиографии. Авторский
`csl-entry` в вопросе с цитатами отклоняется как `BODY.BIBLIOGRAPHY_COLLISION`,
чтобы не подменять generated entries и не удалять авторский контент.

Библиография входит в самостоятельный вопрос. Проверка ID включает
семантические Attr TableHead/Body/Foot, Row и Cell внутри поддерживаемого Pandoc
Table, включая промежуточные строки заголовков тела таблицы. Все его локальные fragment-ссылки
должны иметь цель в condition/publicAnswer, иначе
`BODY.REFERENCE_TARGET_MISSING`. Повторная цель отклоняется как
`BODY.REFERENCE_TARGET_DUPLICATE`. Core не восстанавливает отсутствующие страницы
и не оформляет источники самостоятельно; unsupported-guard остаётся строгим.
Source context допустим только для этого native JSON-прохода; одно авторское
`course-export-context: true` на HTML не обходит website privacy.

Публичность demonstration подтверждается по решению в фактическом публичном
AST этого JSON-прохода, после нативных условий Quarto. Решение с when-format html,
которое отсутствует в JSON, не удовлетворяет stage demonstration выбранного
экспорта. Для переносимой экспортируемой demonstration используйте solution
без format/meta условий. Старый HTML и дополнительный render не используются.
После успешного source run удаление его временного профиля обновляет только
собственное свидетельство конфигурации; отказ не подтверждается такой очисткой.

Внутренний source render явно задаёт `--fail-if-warnings=false`, даже если
публичная конфигурация содержит `fail-if-warnings: true`. Предупреждения native
междокументных ссылок остаются видимыми. Успех определяется нулевой код завершения,
затем проверяются выбранное членство и поддержка Body. Публичный render
сохраняет собственную строгую политику предупреждений; ошибочный участник работы
или некорректное учебное объявление по-прежнему отклоняется.

Исходный проход включает control QMD вне списков публикуемых глав. Публичный
`quarto inspect` задаёт входные документы выбранного банка. Физический владелец
определяется один раз для каждого каталога входов до рендера; Quarto получает
явный список своих источников банка. Вложенные проекты с собственным
`_quarto.yml`/`.yaml` сохраняют самостоятельную область: их вопросы, работы,
повторные ID и ошибки не участвуют и не могут заполнить отсутствующего местного
участника. Банк не ограничивается опубликованными главами.
Физический источник вне банка отклоняется с `EXPORT.SOURCE_OUTSIDE_BANK`.
Алиасы проверяются по физическому владельцу; допустимые алиасы своего банка
рендерятся по правилам Quarto. Кеш и freeze остаются в выбранном банке.

Конфликты ID банка проверяются до выбора. Затем остаются ровно выбранная работа
и её местные участники; проверка возможностей Body выполняется после этого.
Неподдерживаемая неназначенная задача не экспортируется. Неразрешённая ссылка
QRC выбранного условия даёт `BODY.QRC_REFERENCE_UNRESOLVED`.
QRC предоставляет адресные ссылки; чужие тела не импортируются автоматически.

## Публичный и закрытый пакеты

`buildBodies` принимает также явный `DocumentResult` или `ReleaseResult`
успешного завершённого render. `courseId` задаёт логическую идентичность;
`work` — местный ID или `course.id/local-id`. Если работа ровно одна,
производитель может выбрать её автоматически. `sources` необязательно
ограничивает документы. Производитель не запускает render; его вызывающая
сторона проверяет native-завершение. Полные website-факты имеют другую
публичную проекцию: их body.publicExercises не содержит restricted условия.
Поэтому прямой buildBodies(full website) для такой работы даёт
BODY.PUBLIC_FACTS_REQUIRED. Для выдачи restricted используйте collectExport,
затем buildBodies из примера выше; closed payload guards не ослабляются.

Пакет сохраняет schema `course-body-package-v2`. Это отдельная граница от
версии bundle; позиции slots v2 и поля условия проверяются CUE/API
без восстановления старой карты requirements.

Вопросы следуют порядку работы, включая назначенные control и demonstration. Условия и публичные поля
ответов исключают решения, `.correct`, ключи и grading-notes.
`publicPackage` содержит только публичные поля. `includeClosed: true` требует
факты full и отдельно добавляет `closedKey`, `solution`, `gradingNotes`;
ключи из student-фактов не восстанавливаются. Полные native-факты содержат уже
проверенные нормализованные банки ответов для повторного использования.

`slots: AssessmentSlot[]` сохраняет порядок позиций всех task-items работы.
В Body v2 `slots.id` равен `course/work/slot`, `candidates` содержит полные
`course/exr-*`; обычная позиция fixed содержит одного кандидата, random —
минимум двух. `assignment` находится в позиции. Поля `items/assignments` и Body v1
не принимаются. Каталог questions содержит ровно всех кандидатов выбранной работы,
также закрытых для публичной HTML-проекции. Публичный Body содержит безопасные
условия участников без закрытых решений; его slots совпадают с каноническими.

## Ресурсы текущей сборки

`evaluateResources` разрешает выбранные публичные ресурсы, проверяет
принадлежность путей и алиасы; исключает QMD, конфигурацию, служебные файлы,
только скрытые ресурсы и закрытые области проектов заданий.
Body включает разрешённые байты с SHA-256 и заменяет ссылки AST на относительные
`target` пакета, сохраняя query/fragment. Отсутствующие файлы отклоняются.
Сгенерированные ресурсы фиксируются native-фильтром до перемещения или
потребления writer; при приёмке проверяются их digest текущего запуска.
Служебные sidecar не являются публикуемым списком ресурсов.

Student/default сохраняют только публичные сгенерированные байты; full может
сохранять исходные закрытые. Общий публичный ресурс остаётся допустимым.
Области проектов `reference`, `solution`, `solutions`, `tests`, `closed-tests`
и `check.sh` исключаются; авторские `student/tests` могут быть публичными.
Потребитель стартовых файлов явно включает `publicPayload` с фактическим
native-списком авторских входов. Старые локальные результаты не доказывают
успешную сборку. См. [native run API](native-run.md).

Условие аудитории на целой задаче, работе или внешнем контейнере не удаляет
идентичность из исходного выбора. Условия внутри задачи продолжают отделять
публичный текст от full-only материала. Функциональные профили сохраняются и
выбирают варианты задач. Служебный `.course-export-projection` Div переносит
публичный AST в JSON-проходе; адаптеры пропускают его как служебный контейнер,
а не второе авторское объявление.

Причины отказа, доступный контекст и действия автора:
[справочник диагностик](diagnostics.md).

## Метаданные и публичное введение (unreleased)

Body v2 сохраняет `slots` и исходные ключи. В вопросе передаются отдельные
`title`, `difficulty` и `time`: название берётся из канонического заголовка,
время выражено в учебных минутах. При отсутствии авторского значения поле
не добавляется. Для native PrairieLearn читаемое непустое название обязательно;
ID не служит его заменой. Возможности старого пакета и версии consumer нужно
проверять вместе с producer.

Условие не повторяет канонический заголовок и ведущую книжную подпись
Quarto `theorem-title` с номером упражнения. Удаляется только служебный
префикс первого абзаца; авторское продолжение того же абзаца, последующие
подзаголовки и обычный текст сохраняются. Идентификаторы заголовка и вложенных
авторских fragment-целей остаются доступными без повторения текста названия.
Native-подпись уже заменила канонический Header, поэтому следующий авторский
Header сохраняется даже при совпадении названия и уровня. Удаление первого
канонического Header применяется к AST, в котором native-подпись ещё отсутствует.
Presentation metadata удаляются из условия; difficulty/time передаются
отдельными полями для единственного metadata-блока потребителя. Обычный
HTML книги сохраняет штатные подпись и нумерацию Quarto.

`works[].introduction` — публичный AST работы после удаления `.task-items`,
`.assessment-preview`, упражнений банка и закрытых частей. Отсутствующая
свежая native-проекция даёт пустое введение; полное тело не используется как fallback.
Коллектор передаёт `body.publicIntroductionJson` после native writer/shortcodes;
pre-ast `publicAssessment.bodyJson` сохраняет прежний контракт фактов и не служит
готовым введением. Citeproc использует native `resources.effectiveBase`, включая
namespace-qualified источники составной публикации.
Библиография и разрешённые публичные ресурсы введения входят в ту же поставку.

`collectExport` дополнительно возвращает `bodyReferences`; передайте его
`buildBodies`. Контекст связывается с native namespace проекта и публичным
`website.site-url` либо `course-navigation.course-url`. Межпроектные ссылки
разрешает публичный QRC API `entrypoints/body-links.ts` по каталогу текущей
публикации; каталог читается лишь для выбранной содержательной ссылки.
Неизвестная цель диагностируется с источником. Self-target определяется
по canonical namespace/ID; соседняя задача или самостоятельный фрагмент
того же файла сохраняется. Локальная цель внутри вопроса остаётся fragment.
До native экспорта подготовьте публичную композицию и её актуальный каталог.
Планируемый адрес без размещённых материалов не является проверенной целью.
При отсутствии базового URL готовые HTTP(S) ссылки и anchors внутри переносимого
AST сохраняются, очевидная self-ссылка становится текстом. `sourceUrl` в контексте
тогда отсутствует; относительная междокументная адресация и ссылки QRC требуют
публикации и получают предметную диагностику. Ошибки native inspect не скрываются.
