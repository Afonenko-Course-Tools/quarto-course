# Диагностика строк во включённых OJS-ячейках

Дополнительное наблюдение [Core #62](https://github.com/Afonenko-Course-Tools/quarto-course/issues/62#issuecomment-6617170379)
воспроизводится в штатном Quarto без расширений. Компонент — native OJS pipeline
Quarto, который сопоставляет ячейки с исходными строками.

## Минимальный пример

Достаточно двух файлов. `main.qmd`:

```qmd
---
format: {html: {theme: none}}
---

{{< include fragment.qmd >}}
```

`fragment.qmd`:

````qmd
```{ojs}
html`<div id="proof">${6*7}</div>`
```
````

Команда `quarto render main.qmd` успешно создаёт HTML и сообщает:

```text
OJS block count mismatch. Line number reporting is likely to be wrong
```

Этот двухфайловый пример проверен на официальных Quarto **1.11.5 и 1.12.1**.
Дополнительная matrix на **1.11.5, 1.11.6 и 1.12.1** сравнивает одинаковые ячейки
непосредственно в странице и через include: одна включённая ячейка даёт одно
предупреждение, две — два. Прямое размещение предупреждений не даёт. Для двух
ячеек также проверены скрытый setup (`echo: false`, `output: false`), `label`
и `fig-cap`; импорт внешнего модуля для воспроизведения не требуется.

## Установленное влияние

На 12 корректных страницах из этой matrix Chromium по локальному HTTP выполнил
виджет и получил **42**. Для каждой пары direct/include совпали DOM виджета,
подписи и содержимое скомпилированных OJS-программ. Ошибок страницы и загрузки
ресурсов не было.

Отдельный отрицательный контроль показывает конкретную потерю точности:
для `broken = )` непосредственно в странице HTML правильно сообщает строку 11.
При include выражение находится в строке 9 фрагмента; stderr сообщает правильный
номер 9, но не имя файла. HTML callout ошибочно показывает **строку 0**. Номер
из stderr следует сопоставлять с включённым фрагментом; номер в HTML ненадёжен.

Приёмка ограничена этими примерами. Проверка всего Cybersecurity и его предметных
виджетов выполняется отдельно. Предупреждение остаётся неблокирующим для
проверенных корректных native HTML-примеров; оно не означает исправную привязку
номеров строк.

## Причина и дальнейшее действие

Официальный [annotate-source.ts v1.12.1](https://github.com/quarto-dev/quarto-cli/blob/v1.12.1/src/execute/ojs/annotate-source.ts#L24)
читает исходный root QMD. Позднее
[OJS compiler](https://github.com/quarto-dev/quarto-cli/blob/v1.12.1/src/execute/ojs/compile.ts#L285)
получает развёрнутые включённые ячейки; когда список исходных позиций исчерпан,
он использует `cellStartingLoc = 0`. Эта позиция участвует в HTML-диагностике.

Подготовлен точный upstream draft с двухфайловым примером и контролем строки 0;
**он не опубликован**. Существующее упоминание warning в
[Quarto #2700](https://github.com/quarto-dev/quarto-cli/issues/2700#issuecomment-1743512754)
сопровождает другую ошибку lock внешней TypeScript-зависимости и не считается
исправлением либо подтверждённым duplicate этого include case.

Все три проверенные версии сохраняют предупреждение. Исправление относится к
сохранению исходных позиций включённых ячеек в Quarto. Core сохраняет minimum
1.11.5 и явно документирует ограничение HTML line diagnostics; подавление warning,
изменение учебных материалов и изменение Core runtime для этого аудита не нужны.
