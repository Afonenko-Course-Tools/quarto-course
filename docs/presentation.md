# Представление учебных материалов

`course-presentation` оформляет учебные роли, метаданные, подсказки и решения,
описанные в [учебном контракте](../spec/learning-elements.md). Это отдельный фильтр:
он работает с обычными форматами Quarto `html`, `revealjs`, `pdf` и `typst`.
Для оформления штатных упражнений Quarto достаточно самого фильтра; проверку
смысла разметки и выгрузку модели курса обеспечивает `course-core`.

```yaml
filters:
  - course-core
  - course-presentation
format:
  html:
    theme: cosmo
course:
  id: my-course
  view: student
lang: ru
```

Оба фильтра работают на этапе `pre-ast`. **Сначала указывают `course-core`, затем
`course-presentation`**: ядро отбирает содержимое по профилю, проверяет связи и
сохраняет авторские метаданные; фильтр представления оформляет полученный AST.
Для настроенного курса неверный порядок считается ошибкой. Пакет представления
не содержит `contract.json` адаптера оценивания и не регистрирует `target`.

## Разметка учебного блока

Одна запись подходит для книги, слайдов и печатного материала:

```qmd
:::: {#exr-unicode course-role="discussion" difficulty="intermediate" time="5"}
### Длина строки Unicode

Предскажите длину строки, затем сравните свои объяснения.

::: {.callout-tip}
Различайте кодовые единицы и символы.
:::
::::

::: {#sol-unicode}
Результат зависит от того, какие единицы считает выбранное представление строки.
:::
```

Решение задаётся штатным `#sol-*` или ненумерованным `.solution`. Подсказка —
блок `.callout-tip`. Банковское решение связывается по suffix того же QMD либо анонимным
вложением `.solution` в `#exr-*`. У него нет атрибута for; явное for у
допустимой подсказки остаётся отдельной связью. Обычный callout, не связанный с упражнением,
сохраняет стандартное поведение Quarto. Фильтр создаёт внешний контейнер без ID:
идентификаторы, нумерация и перекрёстные ссылки исходных объектов сохраняются.
HTML в авторском тексте не требуется.

Учебные роли получают подписи; собственные `difficulty`/`time` банка и
`stage`/`requirement`/`work-mode` назначений — компактные сведения. Работа может
содержать несколько списков demonstration/classroom/homework; work-mode банка
задаётся на Span ссылки назначения. При `lang: ru` подписи
русские; для англоязычных материалов сохранена локализация `lang: en`.
`time` обозначает оценку времени в минутах.

Метаданные страницы можно одновременно использовать для стандартных списков
Quarto и для упражнений:

```yaml
course-pedagogy:
  document-defaults: true
difficulty: intermediate
time: 45
work-mode: individual
```

Эта настройка относится к standalone педагогическим ролям. В явном
exercise-bank каждая задача имеет собственные обязательные difficulty/time,
не наследует их от страницы и не задаёт work-mode декларации. Атрибуты
конкретного standalone блока имеют приоритет. Вспомогательные роли — например, материалы и
предварительные знания — эту оценку сложности или времени не наследуют.
В `course.json` сохраняются исходные значения; отображаемые метки туда не входят.
Названия в перекрёстных ссылках настраиваются штатным `crossref`, например
`sol-prefix: Решение`.

## Единая презентация и раскрытие ответа

В Reveal создаётся один HTML для аудитории и самостоятельного изучения. Обычная
ссылка открывает режим изучения: общие `.notes` видны рядом со слайдами,
подсказки и решения свёрнуты в `<details>`. Кнопка «Аудитория» скрывает заметки;
кнопка «Изучение» возвращает их. Режим сохраняется только до перезагрузки,
открытые ответы остаются открытыми. Ссылка `slides.html?course-mode=lecture`
явно задаёт аудиторный режим; `course-mode=study` задаёт изучение. YAML `mode`
не используется.

Показ заметок выполняет публичный Reveal `configure({showNotes})`. Штатное
окно по клавише `S` остаётся доступным. Заметки общие и публичные; их не следует
помещать в `.content-visible when-profile=full`. Обычные слайды вне exercise-bank сохраняют авторские решения; банковский
student Reveal подчиняется statementVisibility и demonstration правилам Core.
Решения из банка автоматически не переносятся на отдельные слайды.

```yaml
course-presentation:
  answers: auto     # свёрнуты; expanded — статически раскрыты
```

| Формат | Показ связанных решений и подсказок |
| --- | --- |
| HTML | Штатный сворачиваемый callout Quarto |
| Reveal | `<details>`, доступный мышью и с клавиатуры в обоих режимах |
| Любой формат, `answers: expanded` | Открытые решения и подсказки |
| PDF, Typst, LaTeX | Полное статическое содержимое |
| Печать браузера, Reveal `?print-pdf` | Открытые ответы, callout, фрагменты и все вкладки; заметок нет |

Локальная или QRC-ссылка раскрывает целевой блок и его родителей. Поиск
Navigation включает основной текст, подсказки, решения и общие заметки;
выбор результата раскрывает нужную цель, сохраняя остальное состояние.
Если цель находится в заметках аудиторного режима, открывается только их
штатная панель; режим страницы не меняется. ID остаются у исходных узлов
слайда, копия заметок для показа не добавляет повторных ID.

При обычной печати ответы временно раскрываются, заметки исключаются,
после печати восстанавливается экранное состояние. В отдельной вкладке
`?print-pdf` ответы остаются раскрытыми. Сохраняется крупный слайд; длинные
ответы продолжаются на следующих страницах штатным механизмом Reveal.
Для одной печатной версии каждого слайда задайте `pdf-separate-fragments: false`.
Приватные grading-notes не становятся условием задачи. Политика student/full
для книг определяется профилями и Core отдельно от режима презентации.

## Работы и время

Core передаёт готовые сведения текущего запуска: суммы required/all задач,
отдельное theory-time и две суммы занятия. Presentation не пересчитывает
банковские правила. Назначенная demonstration входит в time, pair/group
не масштабирует его. Preview-ссылка сама не добавляет время примера.
Для partial run недоступные итоги могут отсутствовать или показывать `??`;
старые sidecar и частичная сумма не используются как полный результат.

Assessment-preview остаётся обычным видимым блоком student/full сайта.
Он не назначает задачи и целиком исключается из selected Body экспорта.
Restricted назначения student удалены вместе со ссылками; full показывает
местный состав с ссылками в полный банк, без автоматического копирования тел.

## Таблица плана курса

На главной странице материалы можно собрать в обычную Markdown-таблицу
с классом `.course-plan` в атрибутах самой таблицы. Число колонок, их названия, порядок тем
и ссылки задаёт автор курса. Оформление поставляется `course-presentation` начиная с версии 2.1.1.

Для самостоятельного HTML-портала достаточно подключить этот фильтр:

```yaml
filters: [course-presentation]
format:
  html:
    theme: cosmo
page-layout: full
toc: false
```

```qmd
| Тема | Лекция | Практика | Теория | Исследования | Справочник |
|------|--------|----------|--------|--------------|------------|
| Введение | [Слайды](lectures/01-intro.html) | [Занятие](practice/01-intro.html) | [Понятия](theory/index.html) | [Требования](tasks/index.html) | [Инструменты](handbook/index.html) |

: Материалы курса {#tbl-course-plan .course-plan .striped .hover .responsive}
```

На экране таблица занимает доступную ширину; на узком экране прокручивается
штатным механизмом Quarto для класса `.responsive`. Авторский `div`
или отдельный CSS страницы не требуется. Подпись, ID и ширины колонок
задаются нативными атрибутами таблицы; их оформление не изменяет фильтр.
Строки выровнены по верхнему краю, первая колонка выделяет тему.
Цвета и границы наследуются из темы Quarto. При печати минимальная ширина
снимается, и все колонки остаются в печатном документе. PDF и Typst используют
обычное представление таблиц соответствующего формата.

## Модули и оформление

| Файл | Назначение |
| --- | --- |
| `filter.lua` | Обход AST и подключение зависимостей |
| `modules/config.lua` | Выбор формата, режима и значений документа |
| `modules/metadata.lua` | Подписи ролей и метаданных |
| `modules/answers.lua` | Поиск решений и подсказок, контейнеры раскрытия |
| `disclosure.js` | Раскрытие по локальной перекрёстной ссылке |
| `presentation.js` | Режим страницы через штатные заметки, печать и восстановление состояния |
| `presentation.css` | Размещение блоков, таблиц плана и правила печати |

Для темы доступны классы `.course-block`, `.course-role-*`, `.course-metadata`,
`.course-meta-*`, `.course-answer`, `.course-answer-hint` и
`.course-answer-solution`. После извлечения ядром авторские атрибуты переходят
в `data-course-*`. Цвета задаются переменными `--course-accent`, `--course-muted`,
`--course-border`, `--course-surface`; резервные значения не перекрывают тему.
Cosmo использует переменные Bootstrap. Навигация подключается независимо.

## Проверка

```sh
quarto run tests/presentation.ts
# Нужны Playwright, Chromium и pdftotext:
QUARTO=quarto PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/path/to/chromium \
  node tests/presentation/browser.cjs
```

Проверка рендера охватывает самостоятельный HTML-план, оба режима Reveal,
метаданные, исходные ID, перекрёстные ссылки, вывод LaTeX, неверные настройки
и порядок фильтров.
Браузерная проверка проходит без темы и навигации: переход вперёд, управление
с клавиатуры, ссылки на скрытые ответы, полный текст вкладок и длинного ответа
в PDF, восстановление состояния после печати. Для плана курса проверяются
прокрутка на узком экране и с клавиатуры, переходы по ссылкам, сохранность
обычной таблицы без класса и все колонки в печатном PDF.

## Зависимости HTML

`html-dependency.json` содержит два сценария и одну таблицу стилей. Фильтр регистрирует
их через публичный `quarto.doc.add_html_dependency`. Зависимости устанавливаются
вместе с Core/Presentation/Navigation одним выпуском `quarto-course`; отдельной
авторской настройки или реестра runtime нет.

## Ошибки и исходники демонстрации

`PRESENTATION.CONFIG_INVALID` обозначает неверную настройку;
`PRESENTATION.FILTER_ORDER_INVALID` — неправильный порядок Core/Presentation.
Сообщение содержит входной файл и поле. Standalone Presentation не импортирует
диагностику Core. См. [справочник](diagnostics.md).

Готовая [единая презентация](../examples/course/slides/index.qmd) использует
русские условия, решения и общие публичные заметки. Reveal не обещает HTML
`code-tools`/`code-links`: исходный QMD и целая группа открываются обычными
Markdown-ссылками на закреплённый выпуск репозитория. Дополнительная кнопка
или сценарий для просмотра исходников не нужны.
