# Русский язык README, документации и описаний PR

Новые README, документацию и описания PR во всех репозиториях пользователя
пишите только по-русски. Правило распространяется на курсы и инструменты,
включая организации `BSU-RFCT-Afonenko-Courses` и `Afonenko-Course-Tools`,
а также на авторские инструкции и тексты, подготовленные агентом или
генератором. Заголовки, объяснения, подписи и подсказки шаблонов тоже русские.

Это общий источник языкового правила. Он хранится у `quarto-course` как
редакционная инструкция и не меняет контракт, API или поведение расширений.
Локальные `AGENTS.md` и шаблоны PR ссылаются на этот документ; подробное
правило не копируется в каждый репозиторий. При изменении правила обновите
ссылки и короткие подсказки локальных инструкций и шаблонов.

## Сохранение технического смысла

Используйте естественные русские формулировки и сохраняйте смысл исходного
текста. Команды, идентификаторы API, пути, имена пакетов и URL сохраняйте
буквально. Например, название `SourceSelection`, путь `_quarto.yml`, команда
`quarto render` и ссылка на GitHub остаются в исходном виде; объяснение их
назначения пишется по-русски.

Не переводите имена файлов, ключи конфигурации, значения протоколов и код ради
русификации документа. Язык авторской прозы не меняет формат входных данных.
В документе Quarto используйте поддерживаемое `lang: ru`; эта настройка
локализует и оформляет результат, а русский текст пишет автор или генератор.

## Новый README или документ

Перед созданием текста прочитайте это правило и действующие инструкции
репозитория. Используйте [общий шаблон README](templates/README.md) как
основу, затем заполните его проверенными сведениями о конкретном проекте.
Не переносите в новый документ английские подсказки генератора. Если
генератор выдаёт английский черновик, переведите авторскую прозу перед
сохранением и проверьте технические строки по исходнику.

Документация описывает фактическое поведение и ограничения выбранного Git
ref. Русский текст сам по себе не подтверждает готовность сборки, выпуска,
публикации или внешней интеграции.

## Описание PR

Используйте локальный `.github/pull_request_template.md`. Опишите по-русски
проблему, получившееся поведение, выполненные проверки и реальные ограничения.
Удалите незаполненные подсказки. Автоматически созданный черновик также
приведите к этому правилу перед отправкой PR.

При создании PR через CLI передайте готовый русский текст файлом, например
`gh pr create --body-file /tmp/pr-body.md`. Сохраните в файле настоящие
переводы строк; команды и ссылки не заменяйте пересказом. Применение шаблона
через интерфейс GitHub и подготовка `--body-file` — разные способы работы,
поэтому агент проверяет язык окончательного описания в обоих случаях.

## Проверка результата и существующие материалы

Перед передачей перечитайте новый README, документ или описание PR: авторская
проза и заголовки должны быть русскими, технические строки — совпадать с
исходником, а команды и ссылки — относиться к описываемому проекту. Для
генерируемых текстов проверьте конкретный созданный документ, а не только
инструкцию генератору.

Перевод прежних README, документации и описаний открытых PR выполняется
отдельными партиями задачи A-11. Введение правила и шаблонов в T-13 не
означает завершения этого перевода. До его окончания все новые тексты сразу
создаются по-русски. Исторические снимки исходников, Git история и свидетельства
проверок не переписываются ради перевода старого авторского текста.
