# Справочник диагностик Core и Presentation

Собственные ошибки содержат стабильный ID, русское пояснение и известный
контекст: `source`, `id`, `field`, связанные объекты `related` и подсказку
`hint`. Необязательные сведения выводятся только при наличии. Вне явного банка native `exr-*` не требует банковской роли, difficulty/time
или statement policy. Внутри банка собственные difficulty/time и эффективная
statementVisibility обязательны и проверяются до audience projection.

`source` обозначает входной документ или явно выбранный путь. Include не
получает выдуманную строку QMD: Core знает раскрытый AST, входной документ,
ID и поле. Строки Lua, временного JSON и готового HTML не являются строками
авторского QMD. Сохранённые локальные результаты не доказывают успешный render.

Ошибки останавливают текущую стадию на первом отказе. Проверка Release через
CUE уже использует `--all-errors`. Новый lint или накопитель ошибок не вводится.

## Внешние инструменты и причины

`ExtensionDiagnostic` — имя локального обычного Error с `code`; Lua использует
локальное оформление guard. Это не сериализованный отчёт и не общий пакет.
`ExternalToolFailure` сохраняет инструмент, exit code, stdout, stderr и cause.
Неизвестное внутреннее исключение передаётся native CLI со stack; неизвестная
вложенная причина также сохраняет исходный stack. Обёртка ошибки запуска
применяется только к операционным `Deno.errors`, а внутренний TypeError
сохраняет исходный объект и stack.

CLI печатает ожидаемую ошибку и цепочку исходных причин один раз. Обход
прерывается при повторном объекте Error: циклический cause не повторяет вывод
и не удерживает CLI. CUE rule IDs, Quarto/Gradle и другие внешние сообщения
сохраняются без превращения stderr в новый semantic ID.
`ANSWER_YAML` сохраняет причину YAML parser; `ANSWER_INVALID` в TS —
внешний отказ CUE. Невозможность запуска CUE в TS остаётся внешним отказом,
а не доказательством ошибки авторского ответа. Native Lua сохраняет прежний
`ANSWER_INVALID` и исходную причину; нейтральное пояснение «Не удалось проверить
контракт ответа с помощью CUE» охватывает и отказ запуска, и неуспешную
проверку. Сначала проверьте доступность инструмента и внешний текст,
затем указанное поле. При отказе финальный export не записывается.

Публичный render может включать `fail-if-warnings: true`. Внутренний JSON
source pass выбранного экспорта явно включает `--fail-if-warnings=false`:
междокументные native warnings видимы, но не заменяют проверку выбранного
членства и Body. Ненулевой native exit, ошибочное объявление или отсутствующий
участник по-прежнему завершают экспорт неуспешно. Постоянная конфигурация не
меняется, временный профиль удаляется при успехе и отказе.

## Нативная проекция и порядок потребителей

Raw hasSolution не доказывает публичность. Stage demonstration проверяет
hasPublicSolution после native profile/format/meta условий. В selected JSON
экспорте HTML-only решение может отсутствовать; используйте переносимый
solution без format/meta gating. Отказ остаётся CORE.ASSESSMENT_INVALID,
а дополнительный HTML/исторический результат не подставляется.

Core post сначала завершает native witness и student DTO/AST/resource projection,
затем выполняет full Core/adapter guards и сохраняет run. Поставьте его перед
QRC и другими hooks, читающими публичный результат. Отложенный элемент проходит
публичный этап Core `post-quarto`; его готовая нативная HTML-разметка передаётся
через `quarto.doc.include_text('after-body', ...)` вне `main`. Нативный resolver
книги разрешает адрес и числовую подпись, а native search сохраняет публичные
title/preview без отложенных ссылок. Post переносит разрешённую разметку на место
назначения и удаляет закрытые назначения и служебные контейнеры. Закрытые только
по использованию attachments удаляются, общие публичные ресурсы сохраняются. Strict raw membership и
потребительские guards не отключаются ради неправильной projected модели.

NativeRun свидетельство конфигурации проверяет байты/наличие root и активных profile
файлов. Он не доказывает факт работы процесса при произвольной внешней мутации
hook-кода или конкурентных сборках одного проекта. При несовпадении нет fallback
к прежнему run. Для Source Core удаляет реальный нативный AST-контейнер:
metadata на pre-ast не меняет заранее разрешённые writer options Bootstrap.

## Проверка согласованности

Справочник поддерживается владельцем правил вручную вместе с guard и
отрицательными fixtures. Runtime-реестра и генератора справочника нет.
Учебные объявления проверяют native-document, pedagogy, visibility,
solution-pairing и course-contract; Release — native-release и native-run;
Body/ресурсы — native-body, selected-export, native-resources,
native-project-resources; исходную границу — root-export и
export-bank-ownership; процесс/CLI — system-toolchain; Presentation —
presentation и существующие browser suites. Эти проверки включают
корректные входы, скрытые ошибочные объявления, неизменность правил и
сохранение известных ID/причин.
