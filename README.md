# Programming Course Core

Исполняемая спецификация учебного курса для Quarto. Выделяет задания и состав лабораторных, контрольных и экзаменов из Pandoc AST, объединяет данные независимых расширений и проверяет модель с помощью CUE.

Core 1.2 добавляет opt-in учебную модель `course.schema: "1.1"`: роли деятельности,
предварительные знания, материалы, метаданные сложности/времени/формы работы и связи
упражнений с подсказками и решениями. Курсы на схеме `1.0` сохраняют прежний контракт.
См. [спецификацию учебных элементов](spec/learning-elements.md) и
[архитектуру независимых расширений](spec/plugin-architecture.md).

Вместе поставляются отдельно включаемые `course-presentation` (показ учебных блоков),
`course-navigation` (нейтральное управление Reveal) и `bsu-theme` (только оформление).
Обычные форматы `html` и `revealjs`, стандартные Quarto IDs и crossref сохраняются.

Требования: **Quarto ≥ 1.10**, **CUE ≥ 0.17** для валидации. TypeScript запускается встроенным Deno, Lua — встроенным Pandoc. Отдельные Python и Node.js не требуются.

Рабочий каталог должен находиться в пути без пробелов: это ограничение разбора проектных hooks в Quarto 1.10/1.11. Кириллица допустима.

## Автоматическая проверка

GitHub Actions запускает проверки для PR, изменений в `main`/`master`, вручную и еженедельно. Матрица использует актуальные Quarto `release` и `pre-release`, а также актуальный стабильный CUE; patch-версия Quarto не закреплена. Actions закреплены по SHA и обновляются через PR Dependabot.

Локальный эквивалент из корня репозитория:

```sh
quarto run tests/archive.ts
quarto run tests/publication.ts
quarto run tests/visibility.ts
quarto run tests/downloads.ts
quarto run tests/example.ts
quarto run tests/pedagogy.ts
quarto run tests/core-activation.ts
quarto run tests/presentation.ts
```

Браузерные проверки — отдельная зависимость разработки: `npm ci`,
`npx playwright install chromium`, `npm run test:navigation-model`,
`npm run test:browser`. Для проверки текста созданного PDF нужен `pdftotext`
(пакет Poppler). Использование расширений в курсах не требует Node.js/Playwright.

Проверяются архивы, публикационная схема, видимость HTML и модели, установка текущего расширения и настоящие сборки Quarto с CUE. Отрицательные сценарии требуют отклонения неверной модели, включая повторные ID, неизвестный target и отсутствующее задание занятия. Проверки примеров работают во временных каталогах; отдельный Deno не нужен.

## Установка

```sh
quarto add AfonenkoA/programming-course-core-specification
```

В `_quarto.yml`:

```yaml
course:
  schema: "1.0"
  id: programming
  validate: true
filters:
  - course-core
```

`quarto render` выполняет извлечение и проверку. При ошибке команда завершается неуспешно. `course.validate: false` отключает автоматическую проверку CUE; извлечение AST сохраняется. Для проверки нужен полный рендер проекта, чтобы все выбранные документы были представлены в модели.

## Задания и занятия

Задание — Div с ID, target и первым блоком-заголовком:

````qmd
:::: {#exr-contract target="manual"}
## Контракт функции

Сформулируйте предусловие, постусловие и граничные случаи.
::::
````

`manual` обозначает ручную оценку и входит в ядро. Другие target регистрируются установленными расширениями. Например, PrairieLearn использует `target="prairielearn" project="/projects/clamp"`. Путь `project` отсчитывается от корня проекта Quarto; выход за его пределы запрещён.

Документ занятия:

````qmd
---
assessment:
  kind: lab
---

# Лабораторная 1 {#sec-lab-01}

Подготовка и пояснения.

::: {.assessment-items}
1. @exr-contract
:::
````

`kind` принимает `lab`, `test` или `exam`. Один контейнер `.assessment-items` содержит один список; каждый пункт ссылается ровно на одно упражнение. Порядок пунктов задаёт порядок заданий. Список глав и документов определяет сам Quarto; число лекций, лабораторных и упражнений заранее не объявляется. Вложенные QMD и штатные `include` поддерживаются.

## Результат

После успешной проверки создаётся `_generated/course-spec/course.json`: идентичность курса, зарегистрированные target, задания и занятия с телом Pandoc AST и данными расширений. При новой полной проверке предыдущий результат удаляется; отклонённая модель не получает имя `course.json`.

Проверяются форма узлов, заголовки, атрибуты, уникальность ID, регистрация target, участники занятий, пути проектов и файлов. Ядро не выполняет студенческий код и не определяет жизненный цикл ВМ. Позиция `source` указывает включающий документ, а не строку внутри включения.

Схемы и исполняемые инструменты входят в устанавливаемый пакет `_extensions/course-core/`. Пакет можно переносить вместе с курсом. Контракты адаптеров автоматически находятся в `_extensions`, в том числе при установке с пространством имён владельца.

## Пример

Из корня этого репозитория:

```sh
cd examples/course
quarto add ../..
quarto render
quarto preview
```

Пример использует только ядро: задание с ручной оценкой и лабораторную. Подключения Cloud, PrairieLearn и каталога ссылок ему не нужны.

## Устройство

| Каталог в `_extensions/course-core` | Назначение |
|---|---|
| `domain` | Типы и объединение фактов AST |
| `application` | Сценарий проверки через интерфейсы портов |
| `infrastructure` | Файлы, обнаружение адаптеров, вызовы Quarto и CUE |
| `entrypoints` | Команда проверки и hooks рендера |
| `spec` | Нормативная схема CUE |

Lua-модули разделены на извлечение упражнений, занятий и запись фактов. Markdown повторно не разбирается. [AST-профиль](spec/ast-profile.ebnf) описывает форму узлов; [контракт публикации](spec/cross-references.md) отделён от правил оценки. Для Deno доступны `QUARTO` и `CUE`, если программы установлены вне `PATH`.

## Хранение в Git

Коммитьте исходники расширения в корневом `_extensions/`, спецификации, QMD, ресурсы и `.gitignore`. Установленные копии в `examples/**/_extensions/` и результаты сборки примеров исключены из Git. После изменения расширения повторите `quarto add ../..` из примера, чтобы обновить его копию.

Адрес `AfonenkoA/...` в инструкции — источник установки пакета. Расширение не обращается к этому адресу при сборке. Для форка или локальной копии изменяется только команда `quarto add`.

## Архивы стартовых проектов

`{{< project-download exr-example >}}` создаёт ссылку на архив полного стартового проекта из `student/` упражнения с указанным ID. Архив собирается после проверки модели, не включает соседние `reference/` и закрытые `tests/` и не коммитится. Это работает и для открытых демонстраций `target="manual"`. Формат, ограничения видимости и состав архива описаны в [контракте скачивания](spec/project-download.md).

## Представления курса

Краткий контейнер `::: {.when-full}` включает содержимое только в профиле `full`; `.unless-full` задаёт обратное условие. Суффикс может обозначать любой профиль Quarto. Условия применяются до извлечения модели, поэтому скрытые упражнения не попадают в `course.json`. Для двух версий курса используйте `course.view: student` и `course.view: full` в соответствующих профилях с разными выходными каталогами.

Div `.grading-notes` внутри задания хранит критерии проверки: он автоматически скрыт в студенческом представлении, а в полной модели выделяется в `exercise.gradingNotes` отдельно от условия. Полный контракт, ограничения и примеры находятся в [описании проекций](spec/visibility.md).
