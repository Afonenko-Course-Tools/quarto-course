# Согласованная модель авторской разметки следующего выпуска

Это принятый целевой контракт, ещё не реализованный в текущем выпуске. Порядок
внедрения: [линейный план](../docs/plans/2026-10-08-course-tools-implementation.md).
После реализации перенести правила в актуальные тематические спецификации Core,
пометить их `current`, а этот переходный документ убрать из активной ветки после
сохранения в Git. Документация выпущенной версии ссылается на тот же тег исходников.

## Граница банка и обычного Quarto

`exercise-bank: true` в штатных метаданных `_quarto.yml` или `_metadata.yml`
явно включает модель банка. По умолчанию это `false`; наследование выполняет
Quarto. Только `#exr-*` внутри этой области становятся каноническими задачами.

```yaml
# task/bank/_metadata.yml; соседние страницы работ могут оставаться вне банка
exercise-bank: true
exercise-statement-visibility: open
```

Вне объявленного банка обычные `exr`, `exm`, `sol` следуют стандартному Quarto:
не получают обязательных difficulty/time, банковской приватности и автоматического
включения в модель Course. Имя каталога `task`, тип проекта `book`, `course.id`
и выбор `--book` сами банк не включают. Presentation остаётся явным подключением.

В выбранном native book-проекте остаётся одна область экспортной идентичности
курса. Файлы работ могут находиться вне области канонических задач этого проекта.
Их назначения ссылаются только на задачи объявленного банка. QRC переносит ссылки,
а не чужие условия; вложенные самостоятельные проекты не становятся частью банка.

## Задача и публикация её условия

Каждая каноническая задача имеет собственные обязательные `difficulty` и `time`:
`introductory|intermediate|advanced` и положительное целое число минут. Наследование
сложности или времени от страницы/раздела не поддерживается.

`statement-visibility="open|restricted"` обозначает публикацию именно условия.
Атрибут задачи имеет приоритет над `exercise-statement-visibility` в нативных
метаданных. Эффективное значение обязательно; при отсутствии обоих значений
банковская декларация отклоняется. Невидимого значения по умолчанию нет.

| Банковская задача | Student-сайт | Full-сайт |
| --- | --- | --- |
| `open`, обычная | Условие, без решения | Условие и решение |
| `open`, `course-role="demonstration"`, решение есть | Условие и решение | Условие и решение |
| `restricted` | Условие, решение и ссылка назначения скрыты | Условие и решение |

`course-role="demonstration"` задаёт доступность решения открытой задачи.
Одно открытое условие не делает решение публичным. Stage назначения не переписывает
свойства банковской задачи. Проверяется текущая декларация; метки истории публикаций,
анализ Git/старых рендеров/ранее опубликованного сайта не вводятся.

```qmd
::: {#exr-checksum difficulty="introductory" time="10" course-role="demonstration"}
Покажите, как изменение одного байта влияет на контрольную сумму.

::: {.solution}
Вычисляем сумму исходного файла, изменяем байт и сравниваем результаты.
:::
:::

::: {#exr-collision difficulty="intermediate" time="25"}
Объясните отличие случайной коллизии от намеренного подбора.
:::

::: {#exr-repair difficulty="advanced" time="40"}
Предложите способ проверки повреждённого архива с резервными данными.
:::
```

Пример наследует `open` из показанного `_metadata.yml`. `target` и `project`
остаются явной платформенной привязкой, не способом включить банк. Требования
ведущего заголовка/материалов при такой привязке описывает соответствующий адаптер.

## Решения и педагогические роли

Именованное решение связывается с задачей того же QMD по одинаковому суффиксу:
`#exr-lab-1` → `#sol-lab-1`. Использовать его, если нужна явная ссылка `@sol-lab-1`.
Анонимное `::: {.solution}` внутри задачи использовать, когда ссылка не нужна.
У решения больше нет Course-атрибута `for`; старый синтаксис не поддерживается.
Сохраняется один связанный контейнер решения; альтернативные способы разбора
описываются внутри него обычными заголовками. Сироты, неоднозначные пары и дубли
в каноническом банке отклоняются.

Остаются роли `demonstration`, `discussion`, `objectives`, `prerequisites`,
`reading`, `takeaway`, `limitation`, `misconception`, `criteria`, `deliverables`,
`independent-study`, `control`. В руководстве показать для каждой применимые
контексты и разметку. Роли цели/материалов/критериев описывают смысл блоков;
`independent-study` — педагогическая роль, не отдельный вид работы. Банковская
роль demonstration — единственная из них, дающая указанное выше право на решение.
Нативный `exm` вне банка не является банковской демонстрацией.

```qmd
::: {#exr-lab-1 difficulty="introductory" time="20"}
Вычислите контрольную сумму полученного файла.
:::

::: {#sol-lab-1}
Последовательно проверяем выбранный алгоритм и полученную сумму.
:::
```

При open default это обычное открытое условие; решение доступно только full.
Добавление явной роли demonstration к задаче разрешает показывать его студентам.

## Работа, назначения и stage

Один QMD описывает одну работу. Виды `assessment.kind`: `lab`, `seminar`,
`practical`, `test`; все варианты контроля, включая экзамен, используют `test`.
Вид работы не задаёт форму выдачи, баллы, место выполнения или платформу.
Практическая работа на распечатках имеет `practical` и отдельный QMD рядом
с лабораторной; правила оценивания задаются платформенно.

Сохраняется YAML с `assessment.id`/`kind` и предпочтительная нативная форма
названия/идентичности в заголовке. Вид работы задаётся явно, ID может браться
из существующего `chapter-id` либо первого заголовка:

```qmd
---
assessment:
  kind: seminar
  theory-time: 15
---

# Семинар по целостности данных {#sec-integrity-seminar}

## Разбор с преподавателем

::: {.task-items stage="demonstration"}
1. @exr-checksum
:::

## В аудитории

::: {.task-items stage="classroom"}
1. [@exr-collision]{work-mode="pair"}
:::

## После занятия

::: {.task-items stage="homework"}
1. [@exr-repair]{requirement="optional"}
:::
```

Несколько `.task-items` задают один упорядоченный состав работы. Stage списка:
`demonstration|classroom|homework`. Указывать его явно, когда различие существенно;
у лабораторной без зависимости от места выполнения stage можно опустить.
Скрытого присвоения `classroom` и вывода stage из заголовка нет.

На Span назначения: `requirement="required|optional"` и
`work-mode="individual|pair|group"`; по умолчанию required/individual.
Work-mode относится к назначению в работе, не к банковской задаче.
В каждом пункте одна местная ссылка на задачу; порядок сохраняется.
Повтор задачи в пределах одной работы отклоняется, в разных работах разрешён.

Stage demonstration требует открытого условия, канонической роли demonstration
и фактического публичного решения; отсутствие любого из них — явная ошибка.
В `test` и `practical` назначать только `restricted`. Демонстрационные примеры
для этих работ размещаются обычными ссылками в `.assessment-preview`, вне состава.

## Предварительное описание сайта и экспорт

`.assessment-preview` показывается на student/full сайте и полностью исключается
из экспорта. Это текст и обычные ссылки на примеры; он не объявляет задачи
и не назначает их в работу. Дополнительный профиль для него не вводится.

```qmd
---
assessment:
  kind: practical
---

# Практическая работа на распечатках {#sec-integrity-practical}

::: {.assessment-preview}
Работа проводится в аудитории. Перед ней изучите разбор @exr-checksum.
Проверяется объяснение причин, а не только итоговый ответ.
:::

::: {.task-items stage="classroom"}
1. @exr-integrity-variant
:::
```

`exr-integrity-variant` объявляется в банке со своими difficulty/time,
`statement-visibility="restricted"` и решением. Student показывает название
работы и общедоступное описание, без ссылок на закрытые назначения. Full позволяет
прочитать все назначенные условия и решения в полном банке; автоматическое
дублирование богатых тел задач на странице работы не входит в этот этап.

Экспорт содержит только выбранные назначенные условия, поля ответа и их ресурсы.
Заголовок/ID работы сохраняются как метаданные; внешние заголовки занятия,
preview и окружающая проза не экспортируются. Внутренние заголовки условия —
часть самой задачи и сохраняются. Последовательность занятия оформляется
обычными Markdown-заголовками/оглавлением; особого блока `.step` нет.

Restricted означает отсутствие условия на открытом сайте, но разрешает его
выдачу участнику выбранного Print/PrairieLearn экспорта. Это не право на
closedKey, solution или gradingNotes: они остаются отдельным закрытым payload.
Moodle получает нужные преподавательские ключи по собственному контракту.
Существующее Body `visibility: public` означает безопасную часть выдачи участнику,
а не публикацию условия на сайте; его guards не ослаблять ради restricted.
Вопрос Body получает отдельное `statementVisibility: open|restricted` из банка.
Print/PL принимают restricted с participant-safe condition и прежними запретами
ключей; проверка test/practical касается statementVisibility. Не переименовывать
публичные ресурсы или private partitions в значения политики условия.
Student HTML/search/QRC/resources/ZIP не должны сохранять удалённые закрытые тела.

## Время занятия

Сумма обязательных задач и сумма всех задач рассчитываются по собственным time
назначений, включая demonstration. Работа в паре/группе время не масштабирует.
Необязательное `assessment.theory-time` — положительное конечное число минут на изучение
теории вне уже учтённого времени задач. Оно добавляется один раз для двух
рекомендательных итогов занятия; показывать отдельно суммы задач и время теории.

В примере семинара: задачи required — 35 минут, all — 75 минут; теория — 15;
занятие required — 50, all — 90. Ссылка на пример из preview автоматически
не включает его time; при необходимости её изучение учитывает автор в theory-time.

Полный render/экспорт проверяет назначения по полной текущей модели. Частичный
render/preview может пропустить недоступный итог или показать `??`. Нельзя выдавать
частичную сумму за полную, подставлять 0 или брать данные из старых sidecar;
дополнительный полный render ради preview не выполняется.

## Служебная модель и границы реализации

Сохранить `items: string[]` в порядке авторского состава. Поля назначения
хранить одной картой `assignments[id] = {stage?, requirement, workMode}`,
заменив старую карту requirements; единообразно обновить Core/CUE/Body/адаптеры.
Это транспорт результата, не второй авторский синтаксис.

До student-проекции проверить raw декларации и сохранить только необходимые
канонические факты: ID/source, собственные difficulty/time, эффективный
statementVisibility, role/наличие решения и его фактическая доступность в
публичной проекции. Закрытые AST в student результат не
сохранять. Междокументные проверки и суммы выполнять в существующей текущей
NativeRun/Release сборке, не вводя парсер Markdown, вторую модель курса,
общий registry или новый полный проход. Проверки самостоятельных API/CUE/Body
сохранить, даже если часть их правил пересекается.

## Версия, диагностика и Windows

Базовая поддерживаемая версия Quarto — 1.11.5; поддержка 1.10.x удаляется
из активных workflows, README, дескрипторов, руководств и примеров. CUE — 0.17.1.
Новые релизы, код и документация обновляются согласованно, без старых aliases.

Собственные сообщения — по-русски, существующие ID сохраняются. Небольшая
локальная `diagnostic(code,message,context?,cause?)` возвращает обычный Error
с code; context содержит известные source/id/field/related/hint. Для узкой CLI
границы используются имена ExtensionDiagnostic/ExternalToolFailure; общей
импортируемой иерархии, report schema и накопителя ошибок нет. Внешний отказ
сохраняет инструмент, код, stdout/stderr и cause; неизвестный stack не гасится.
CUE `--all-errors` остаётся, общий recovery не добавляется. Строки QMD
не придумываются по позициям временного JSON/HTML/Lua.

Публичный курс использует нативные `fail-if-warnings: true` у подпроектов;
Lua warning при необходимости идёт через `pandoc.log.warn`. Внутренний source
JSON pass не наследует эту строгость автоматически. Exit 0 со stderr не считается
отказом, regex-разбор чужих предупреждений не вводится. Справочники диагностик
принадлежат владельцам; ошибочные fixtures остаются внутренними тестами.

Перенести только подтверждённые Windows-патчи: сравнение путей NativeRun
с нормализацией разделителей без изменения IO-путей и CUE temp JSON внутри
projectRoot с finally cleanup. Новые Windows проблемы решаются после реального
воспроизведения в локальной сессии; широкая Windows CI matrix не входит в план.
Отдельно документировать upstream `recoverEncode` на кириллическом пути в Quarto
1.11.5 и временный путь без кириллицы, не объявляя ошибку Quarto исправленной.
