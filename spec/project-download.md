# Архив стартового проекта

Ссылка на архив относится к упражнению, а путь к проекту задаётся один раз — атрибутом `project`:

```qmd
:::: {#exr-example target="manual" project="/examples/example"}
## Исследование поведения программы

Условие задания.

{{< project-download exr-example >}}
::::
```

Допустим необязательный аргумент `text="Скачать исходники"`. Других аргументов нет. Shortcode может стоять внутри или после упражнения, но ссылка и видимое упражнение должны принадлежать одному документу. `target` не ограничен PrairieLearn: демонстрация с `target="manual"` не становится платформенным вопросом.

`project/student/` — полный самостоятельный стартовый проект. В него входят собственные инструкции, файлы сборки, заготовки и открытые тесты. При распаковке `student/` снимается: содержимое становится корнем проекта. Авторское решение и закрытые тесты хранятся вне этого каталога, например в соседних `reference/` и `tests/`. Нельзя помещать закрытые материалы внутрь `student/` и рассчитывать на их распознавание по имени.

После ранней фильтрации видимости штатный механизм Quarto раскрывает shortcode; отдельный фильтр превращает его в обычную относительную ссылку; в модель попадает заявка `{exercise, source}`. Только после проверки модели CUE post-render создаёт `_downloads/<exercise-id>.zip` внутри текущего output-dir. Для этого требуется `course.validate: true`. Неизвестное, скрытое упражнение или упражнение без проекта является ошибкой. Повторы одной ссылки в документе дают один архив. Идентификатор упражнения определяет имя архива; имя каталога курса, его владелец и структура вложенности не участвуют.

Архив включает только обычные файлы из `student/`. Символьные ссылки в пути проекта или внутри стартового проекта отклоняются; выход за корень курса запрещён. Исключаются каталоги `.git`, `.quarto`, `.gradle`, `.idea`, `.vscode`, `build`, `target`, `out`, `node_modules`, `__pycache__`, `_generated`, `_book`, `_site`, `_output`, `_downloads`, файлы `.gitkeep`, `.DS_Store`, скомпилированные `.class` и `.pyc`. ZIP детерминирован: порядок файлов и даты записей фиксированы. Отдельный архиватор не требуется.

Архивы не хранятся в Git. При новой сборке каталог `_downloads` текущего профиля очищается; скрытый shortcode не создаёт заявку и архив. Quarto output-dir каждого профиля должен отличаться от исходного дерева. В составной публикации готовый каталог `_downloads` переносится вместе с результатом подпроекта; ссылки сохраняются под префиксом сайта.

Профили ограничивают опубликованный результат. Если исходный репозиторий открыт, его история, `reference/`, `tests/` и полный QMD доступны посетителям GitHub независимо от профиля.

В IR тело упражнения остаётся авторским Pandoc AST, включая исходный shortcode. Будущий компилятор платформенных условий должен разрешить его как издательскую ссылку или опустить; он не должен включать закрытые исходники. Для создания самого архива используются только проверенные заявки `downloads`, а не повторный разбор текста.
