# Учебные элементы

Quarto/Pandoc разбирает Markdown, идентификаторы, ссылки и заголовки. Core
извлекает учебные факты из фактического AST, включая native include и результат
вычислений. Обычная книга или слайды не требуют `course.id` и адаптеров.

## Задача, пример и решение

```qmd
::: {#exr-checksum}
Объясните, почему контрольная сумма обнаруживает изменение сообщения.
:::

::: {#exm-checksum}
Пошаговый пример вычисления контрольной суммы.
:::

::: {#sol-checksum for="exr-checksum"}
Разбор задачи обычным Markdown.
:::
```

`exr-*`, `exm-*` и `sol-*` остаются нативными идентификаторами Quarto.
Каждый `exr-*` извлекается как Exercise. `course-role`, `difficulty`,
`target`, `project`, окружающий `sec-*` и ведущий заголовок не обязательны для
обычной задачи. Нативный пример/решение может существовать самостоятельно;
совпадение суффиксов не является условием допустимости.

Для явной связи решения используйте `for="exr-checksum"` или вложите решение
в задачу/пример. Core также сохраняет однозначную существующую пару по суффиксу.
Неоднозначный суффикс не создаёт связь. Явная отсутствующая или противоречивая
цель `for` отклоняется. Дублирующиеся ID и вложенные канонические задачи
отклоняются. Авторские атрибуты сохраняются; неизвестные платформенные поля
проверяет выбранный адаптер.

Явный `target="manual"` либо имя зарегистрированного адаптера означает
платформенную привязку. Для неё требуется ведущий Header внутри задачи;
Core не добавляет `manual` к обычной задаче. Поле `project` указывает локальные
авторские материалы выбранного адаптера, а не способ вычисления обычного Markdown.

## Необязательные метаданные

| Атрибут | Значения / смысл |
|---|---|
| `course-role` | `demonstration`, `discussion`, `independent-study`, `control` |
| `difficulty` | `introductory`, `intermediate`, `advanced` |
| `time` | Положительное число минут |
| `work-mode` | Значения единого словаря контракта, например `individual`, `pair`, `group` |
| `for` | Явная связь учебного блока с задачей/примером |

Если атрибут указан, его значение проверяется. Эти поля помогают читателю
понять задачу; они не задают баллы, попытки, сдачу или grader. Блоки
`.prerequisites` и `.reading` сохраняют обычные ссылки и структуру Pandoc.
Окружающий заголовок может дать `sourceTopic`; он не назначает владельца задачи.
Полный словарь находится в `_extensions/course-core/contract-vocabulary.json`.

## Работа и раздатка

Работа содержит один явный список местных задач `.task-items`:

```qmd
---
title: Контрольные суммы
assessment:
  id: checksum-lab
  kind: lab
---

# Контрольные суммы

::: {.task-items}
1. @exr-checksum
2. [@exr-collision]{requirement="optional"}
:::
```

`assessment.id` — устойчивый локальный ID работы. Если он отсутствует,
используется `chapter-id` или ID первого заголовка. Это не требует префикса
`sec-*`. Виды: `lab`, `test`, `exam`, `handout`. Без `assessment.kind`
список является неоцениваемой раздаткой `handout`.

Для `lab/test/exam` задача по умолчанию обязательна (`required`);
`requirement="optional"` на Span ссылки делает назначение необязательным.
Явный `requirement="required"` тоже допустим. Для раздатки статус не требуется.
Статус относится к включению в работу, а не к самой задаче: одну задачу можно
назначить по-разному в разных работах. В модели сохраняются `items: string[]`
и, при наличии статусов, `requirements: {"exr-id": "required"|"optional"}`.

Каждый пункт содержит одну местную ссылку `@exr-*`; порядок сохраняется.
Повтор задачи, повтор статуса, неизвестное значение, несколько списков и
несуществующий выбранный член отклоняются. Текстовая ссылка вне `.task-items`
не включает задачу в экспорт. Старые `.assessment-items` и `.print-items`
не поддерживаются. Межпроектная QRC-ссылка не включает чужое условие.

## Ответы и публикация

`.answer` с одной отметкой `.correct` задаёт single-choice. YAML-блок
`.answer-spec` поддерживает manual, numeric, multipart и matching по
`body-export/answer.cue`. Банк относится ровно к одной задаче/примеру;
ключи проверяются на raw AST один раз до проекции видимости. `.grading-notes`
относится к одной задаче и извлекается отдельно от условия.

Student удаляет ключи, grading-notes и закрытые решения обычных задач книги;
публичное решение демонстрации/примера сохраняется. Reveal сохраняет авторские
решения на слайдах, а шаги показа задаются штатными `.fragment`.
Control-страницы исключаются автором из native student file lists.
См. [видимость](visibility.md), [представление](../docs/presentation.md) и
[выбранный экспорт](../docs/body-export.md).
