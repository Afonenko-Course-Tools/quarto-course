# Учебные элементы: смысл, связи и метаданные

Учебный контракт задаёт смысл блоков и связи между ними. Он действует при
подключённом `course-core` и не имеет переключателя версии в YAML. Поддерживается
только текущая согласованная реализация ядра, схем и адаптеров.

Форматы остаются штатными `html` и `revealjs`. Раскрытие ответа обеспечивает
`course-presentation`, навигацию — `course-navigation`, шрифты и цвета — тема.
Эти настройки представления не входят в смысловую модель. Адаптеры оценивания
дополняют `exercises` и `assessments`; учебный блок без `target` не становится
оцениваемым заданием.

## Штатные объекты и небольшой словарь ролей

Определения, теоремы, примеры, упражнения и решения сохраняют нативные ID
`def-*`, `thm-*`, `exm-*`, `exr-*`, `sol-*`, нумерацию и ссылки Quarto.
Новая роль задаётся одним атрибутом обычного fenced Div, а не HTML-разметкой
или отдельным языком вложенных блоков.

| `course-role` | Значение |
|---|---|
| `demonstration` | Демонстрация метода или приёма |
| `prediction` | Прогноз до показа объяснения |
| `discussion` | Вопрос для обсуждения |
| `self-check` | Самопроверка |
| `objectives` | Цели обучения |
| `prerequisites` | Предварительные знания и необходимые материалы |
| `reading` | Чтение и дополнительные ресурсы |
| `takeaway` | Вывод или ключевой тезис |
| `limitation` | Ограничение применимости |
| `misconception` | Типичное заблуждение или ошибка |
| `criteria` | Публичные критерии оценки |
| `deliverables` | Что нужно предоставить в результате задания |

Первые четыре роли могут уточнять нативный `exr-*`. Остальные используются
на обычном Div или совместно с подходящим нативным callout. Не нужно выбирать
callout только для хранения сложности или времени. Обобщённый вопрос можно
записать обычным нативным упражнением без `course-role`.

````qmd
::: {#exr-predict course-role="prediction" difficulty="introductory" time="5" work-mode="pair"}
## Прогноз поведения коллекции

Что изменится при добавлении повторяющегося значения?
:::

::: {#sol-predict for="exr-predict"}
Объяснение с примером и ссылкой на спецификацию языка.
:::
````

`target` — единственный признак задания, извлекаемого в
`course.json.exercises`. Нативный `#exr-predict` без `target` попадает только
в учебный индекс `pedagogy`; он не увеличивает число оцениваемых заданий и
не включается автоматически в состав лабораторной или контрольной.

## Метаданные заданий и деятельности

| Атрибут | Допустимые значения | Значение |
|---|---|---|
| `difficulty` | `introductory`, `intermediate`, `advanced` | Уровень сложности; интерфейс может подписать их У1, У2, У3 |
| `time` | Целое число от 1 до 1 000 000 | Оценка времени в минутах, без запуска таймера |
| `work-mode` | `individual`, `pair`, `group` | Индивидуальная, парная или групповая работа |
| `requirement` | `required`, `recommended`, `optional` | Обязательность ресурсов; только на `course-role="reading"` |

Первые три атрибута допустимы на `exr-*` и четырёх ролях деятельности.
Они необязательны: отсутствие значения не означает «лёгкое», «ноль минут»
или «индивидуально». Для `target`-упражнений расширен список допустимых
атрибутов; неизвестные атрибуты отклоняются CUE-проверкой.

Для страниц заданий, уже участвующих в нативных списках Quarto, используйте
один источник метаданных:

```yaml
course-pedagogy:
  document-defaults: true
difficulty: intermediate
time: 90
work-mode: individual
```

Опция может находиться в конфигурации проекта, а значения — в YAML каждой
страницы. Core читает ровно три верхнеуровневых поля; стандартный список
продолжает читать `difficulty` без производного файла или своего механизма разрешения ссылок.
Их наследуют упражнения и деятельности данного документа. Локальные
атрибуты имеют приоритет. Вспомогательные блоки — например prerequisites
или reading — сложности и времени не наследуют.

Неизвестные опции `course-pedagogy`, неверные типы и значения проверяются
даже на странице без упражнений. Без явного `document-defaults: true`
Core не интерпретирует одноимённые метаданные документа.

## Предварительные знания и материалы

Содержимое остаётся обычным Markdown: списками, ссылками, цитатами и ссылками
Quarto Reference Catalog. Core сохраняет исходный Pandoc AST; он не вводит
вторую таблицу ID, новый синтаксис URL, граф зависимостей или отдельный
алгоритм разрешения межпроектных ссылок.

````qmd
:::: {#exr-essay target="manual" difficulty="advanced"}
## Реферат: выбор реализации коллекции

::: {course-role="prerequisites"}
- [Документация Java Collections](https://docs.oracle.com/en/java/)
- Изученный материал по интерфейсам и обобщённым типам.
:::

::: {course-role="reading" requirement="required"}
- [Руководство и API Java](https://docs.oracle.com/en/java/)
:::

::: {course-role="deliverables"}
- Текст реферата и список использованных источников.
- Сравнительный пример с объяснением выбора.
:::

::: {course-role="criteria"}
- Корректность аргументации.
- Связь выводов с приведёнными источниками.
:::
::::
````

Вложенные учебные блоки относятся к ближайшему окружающему `exr-*`.
Вне упражнения связь задаёт `for="exr-id"`. Например, отдельный список
prerequisites может стоять перед заданием и явно ссылаться на него.

## Подсказки и объяснения

Подсказка — стандартный `.callout-tip`, связанный с упражнением через `for`
или находящийся внутри упражнения. Решение — нативный `#sol-*` либо
безымянный `.solution`. Нумерованные решения имеют собственные нативные ID;
совпадение суффиксов `exr-name` и `sol-name` само по себе связи не создаёт.

````qmd
::: {.callout-tip for="exr-essay"}
Сначала сформулируйте критерий выбора, затем сравните реализации.
:::
````

Явный `for` должен указывать на видимый `exr-*` в **том же документе**.
Это может быть нативное упражнение без `target`. Несуществующая цель,
повторный ID и конфликт с окружающим упражнением — ошибки. Несколько подсказок
или решений разрешены: их порядок задан исходным документом. Межпроектный
переход к чужому заданию остаётся обычной ссылкой QRC внутри содержимого.

`.grading-notes` остаётся отдельным закрытым контрактом для преподавателя.
Он не является публичным ответом или публичными критериями. В представлении
student его нет ни в HTML, ни в модели; в full он хранится отдельно в
`exercise.gradingNotes`. Даже в full этот текст не дублируется в `pedagogy`.

## Машинная модель и порядок обработки

После профильной проекции Core собирает `pedagogy.elements`. Каждый элемент
содержит `kind`, `body` в Pandoc AST, `source` и `order`. Необязательные поля —
`id`, `exercise` (связь с заданием), `title` и `metadata`.
`title` берётся из атрибута `title` либо первого блока-заголовка; подпись
интерфейса для роли не подменяет авторский заголовок. `order` — порядок обхода
элементов в одном включающем документе, начиная с 1; это не постоянный ID.

`kind` равен роли либо `exercise`, `solution`, `hint`. Собственное `exercise`
у элемента-упражнения отсутствует. Для унаследованных значений документа
отдельно сохраняется `pedagogy.documents[{source, defaults}]`; каждое задание
также содержит свои эффективные значения. Модель использует `workMode`, остальные
имена метаданных совпадают с авторскими. Родительский `body` может содержать
вложенные учебные блоки: плоский индекс предназначен для поиска и анализа,
а исходный AST — для сохранения содержимого и структуры.

1. Quarto раскрывает include и формирует AST.
2. Core выполняет существующую профильную проекцию и отделяет grading-notes.
3. Модули `pedagogy/contract.lua` и `pedagogy/collect.lua` проверяют значения,
   строят индекс видимых упражнений и извлекают факты.
4. Независимый фильтр представления использует исходные атрибуты, сохранённые
   Core, и выбирает fragment, disclosure или печатный вид.
5. После рендера доменный модуль объединяет факты документов; CUE проверяет
   модель и связи перед публикацией `course.json`.

Скрытое профилем упражнение не может быть целью видимого `for`: ссылка
отклоняется. При печати раскрываются опубликованные ответы; удалённые
профилем материалы обратно не появляются. Проверка фактического результата
шага, выполнение кода, интерактивное тестирование ответа и таймер в контракт
не входят. Колонки, вкладки, код, формулы и диаграммы остаются средствами Quarto.
