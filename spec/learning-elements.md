# Учебные элементы

Quarto/Pandoc разбирает Markdown, идентификаторы, ссылки, include и результат
вычислений. Core извлекает факты текущего AST. Обычный Quarto-документ и
самостоятельные Presentation/Navigation не требуют банка, `course.id` или адаптера.
Это текущий контракт Core 5.0.0 того же Git ref. Выпущенные правила читаются
по неизменяемому тегу; [индекс](index.md) определяет владельцев и версию.

## Явная область банка

Только `exercise-bank: true` в штатных `_quarto.yml` или `_metadata.yml`
включает канонические банковские задачи. По умолчанию банк выключен;
наследование метаданных выполняет Quarto. Имя каталога, `project.type: book`,
`course.id` и параметр экспорта `--book` не включают банк.

```yaml
# tasks/_metadata.yml
exercise-bank: true
default-exercise-statement-visibility: open
```

В этой области `#exr-*` становится `Exercise`. Каждая задача обязана иметь
итоговые `difficulty="introductory|intermediate|advanced"` и `time` — положительное
целое число минут. Они берутся из индивидуальных атрибутов либо `default-exercise-difficulty/time` в объединённых Quarto metadata; произвольные difficulty/time страницы не являются этими defaults.
`statement-visibility="open|restricted"` имеет приоритет над нативным
`default-exercise-statement-visibility`; эффективное значение обязательно.

Вне банка `exr`, `exm`, `sol` сохраняют стандартное поведение Quarto и не входят
автоматически в Course. Для них не требуются банковские difficulty/time,
политика условия или связанное решение. Нативный `exm` не объявляет банковскую
демонстрацию. Presentation подключается явно.

```qmd
::: {#exr-checksum difficulty="introductory" time="10" course-role="demonstration"}
Покажите, как изменение одного байта влияет на контрольную сумму.

::: {.solution}
Вычисляем сумму исходного файла, изменяем байт и сравниваем результаты.
:::
:::

::: {#exr-collision difficulty="intermediate" time="25"}
Объясните отличие случайной коллизии от намеренного подбора.
:::
```

Пример наследует `open` из `_metadata.yml`. `target="manual"` или выбранный
адаптер остаётся отдельной платформенной привязкой; его правило ведущего Header
и `project` не включают банк. Окружающий `sec-*` может дать `sourceTopic`,
но не назначает владельца задачи. Дублирующиеся ID и вложенные банковские
задачи отклоняются до проекции аудитории.

## Решения

Для ссылки на решение используйте ID с тем же суффиксом и задачу того же QMD:

```qmd
::: {#exr-lab-1 difficulty="introductory" time="20"}
Вычислите контрольную сумму полученного файла.
:::

::: {#sol-lab-1}
Последовательно проверяем алгоритм и полученную сумму.
:::
```

Если ссылка не нужна, используйте анонимное `::: {.solution}` внутри задачи.
У банковского решения атрибут `for` не поддерживается. Допускается один
связанный контейнер; альтернативные разборы помещайте в нём обычными заголовками.
Сироты, неоднозначные пары и дубли отклоняются. `for` у допустимых подсказок
и других педагогических блоков сохраняет своё отдельное значение.
Публичное решение требует открытой задачи с `course-role="demonstration"`;
правила student/full определяет [видимость](visibility.md).

## Педагогические роли

`course-role` задаёт смысл блока, например `::: {course-role="reading"}`.
Обычные ссылки и структура Pandoc сохраняются. CSS-класс сам не заменяет
явное объявление роли. Роли не задают баллы, попытки,
место выполнения или платформу.

| Роль | Контекст и назначение |
| --- | --- |
| `demonstration` | Разбор деятельности; у открытой банковской задачи разрешает публичное решение |
| `discussion` | Вопрос для обсуждения в тексте или банковская задача |
| `objectives` | Цели страницы, темы или работы |
| `prerequisites` | Предварительные знания и навыки |
| `reading` | Ссылки на материалы; допускает required/optional |
| `takeaway` | Основной вывод темы или разбора |
| `limitation` | Граница применимости метода |
| `misconception` | Типичная ошибка и её объяснение |
| `criteria` | Критерии результата в описании работы или задачи |
| `deliverables` | Что сдаёт участник |
| `independent-study` | Самостоятельная деятельность; не отдельный вид работы |
| `control` | Контрольная деятельность; сама роль не скрывает условие |

У канонической задачи допустимы роли деятельности: demonstration, discussion,
independent-study, control. Остальные роли оформляют смысловые блоки вокруг
задачи или внутри неё. `work-mode` относится к назначению банковской задачи,
а не к её декларации. Правила необязательных метаданных standalone педагогических
блоков не заменяют обязательные собственные поля банка.
Полный словарь: [contract-vocabulary.json](../_extensions/course-core/contract-vocabulary.json).

## Одна работа и несколько списков

Один QMD описывает одну работу с явным `assessment.kind`: `lab`, `seminar`,
`practical`, `test`. Экзамен использует `test`; практическая работа на распечатках —
`practical`. Вид не определяет доставку или оценивание. ID задаётся
`assessment.id`, существующим `chapter-id` или первым заголовком.

```qmd
---
assessment:
  kind: seminar
  theory-time: 15
---

# Семинар по целостности данных {#sec-integrity-seminar}

## Разбор с преподавателем

::: {.task-items stage="demonstration"}
1. @exr-checksum
:::

## В аудитории

::: {.task-items stage="classroom"}
1. [@exr-collision]{work-mode="pair"}
:::

## После занятия

::: {.task-items stage="homework"}
1. [@exr-repair]{requirement="optional"}
:::
```

Несколько `.task-items` объединяются в один состав в порядке документа.
Каждый пункт содержит одну местную `@exr-*` ссылку. Повтор задачи в одной работе
отклоняется; в разных работах разрешён. QRC-ссылка не импортирует чужое условие.
`stage="demonstration|classroom|homework"` задаётся списку и может отсутствовать:
скрытого classroom или вывода stage из заголовка нет. В служебном API допустимо
только отсутствие stage либо одно из этих значений; явные null/пустая строка
отклоняются независимо от Lua/CUE проверки.
На Span ссылки допустимы `requirement="required|optional"` и
`work-mode="individual|pair|group"`; defaults — required и individual.
Stage не меняет свойства банковской задачи.

Demonstration требует открытого условия, канонической роли demonstration и
фактического публичного решения после нативных условий Quarto. Raw hasSolution
сам по себе недостаточен; проверяется hasPublicSolution. Для выбранного JSON
экспорта HTML-only решение не подтверждает demonstration: используйте
переносимый solution без format/meta условий. В practical/test назначаются только restricted
задачи. Открытые примеры для этих работ помещайте обычными ссылками в
`.assessment-preview`: это видимый текст сайта, полностью исключённый из экспорта.
Обычная ссылка вне task-items не назначает задачу. Последовательность занятия
оформляется штатными заголовками; специального блока step нет.

## Время и транспорт

Суммы required/all включают собственное time всех назначений, включая
demonstration; pair/group его не масштабируют. Необязательное
`assessment.theory-time` — положительное конечное число минут на теорию вне
уже учтённых задач. Оно один раз добавляется к двум итогам занятия.
В примере с третьей задачей `time="40"`: задачи required — 35, all — 75;
теория — 15; занятие required — 50, all — 90 минут.
Preview-ссылка не включает время примера автоматически.

В модели сохраняются ordered `items: string[]` и одна карта
`assignments[id] = {stage?, requirement, workMode}`; `theoryTime` хранит время
теории. Старой карты requirements нет. Это служебный транспорт, а не второй
авторский синтаксис. Полная текущая сборка строго проверяет назначения;
частичный preview пропускает недоступный итог или показывает `??`, без ложного
нуля, частичной полной суммы и чтения старых результатов.

## Ответы и экспорт

`.answer type="single-choice"` с одним BulletList и одной `.correct`
отметкой на Span задаёт single-choice. `.answer-spec`
поддерживает manual, numeric, multipart и matching по
[answer.cue](../_extensions/course-core/body-export/answer.cue).
Ключи проверяются до проекции; `.grading-notes` хранится отдельно от условия.
Экспорт выбранной работы передаёт participant-safe restricted условие,
поля ответа и ресурсы. Решения, ключи и grading-notes отделяются в закрытый
payload. Preview, внешние заголовки занятия и окружающая проза исключаются;
внутренние заголовки условия сохраняются. См. [Body](../docs/body-export.md).
