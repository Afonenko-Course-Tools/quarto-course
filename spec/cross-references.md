# Публикация книги и слайдов

Учебная модель и издательская структура независимы. Course Core проверяет задания и занятия; Reference Catalog связывает HTML-объекты нескольких самостоятельных проектов Quarto.

## Структура

Корневой проект имеет тип `website` и подключает `reference-catalog`. Подкаталоги `book`, `lectures` и `practice` содержат собственные `_quarto.yml`. В книге список документов определяется `book.chapters` и `book.appendices`; у слайдов — `project.render`. Произвольный обход всех QMD вместо выбора Quarto не применяется.

```yaml
project:
  type: website
  output-dir: _site
  render: []
filters: [reference-catalog]
reference-catalog:
  namespace: site
  home: book
  projects:
    book: {path: book, format: html}
    lectures: {path: lectures, format: revealjs}
    practice: {path: practice, format: revealjs}
    essay: {path: essay, format: html}
```

`home` задаёт проект, размещаемый в корне публикации. Он должен иметь формат HTML и выдавать `index.html`. Его дерево вывода публикуется целиком; все внутренние пути сохраняются. Для этого проекта `mount` не задаётся. Корневой `render: []` оставляет рендер документов подпроектам; внешний index не создаётся.

Без `home` допускается обычная страница портала в корневом проекте. Подпроекты тогда размещаются в каталогах, определяемых `mount` либо пространством имён.

Набор подпроектов не фиксирован: `essay` — пример дополнительной книги с собственными главами и профилями. Поле `format` необязательно: Reference Catalog использует `html` для пространства имён `book`, иначе `revealjs`. Для дополнительных книг указывайте `format: html` явно. Если главной страницей выбран пространство имён, отличный от `book`, схема требует явно записанный `format: html`; для `home: book` достаточно значения по умолчанию. Проверка этих случаев: `quarto run tests/publication.ts`.

## Идентичность ссылок

`@book:fig-layout`, `@lectures:sec-memory` и `@practice:exr-clamp` задают пространство имён и явный ID. Номер и подпись определяет проект назначения. При переносе файла или изменении `output-file` ID сохраняется, а опубликованный URL пересчитывается.

Книга и слайды могут ссылаться друг на друга. Сначала каждый проект рендерится независимо, затем собираются все цели и разрешаются ссылки. Цикл ссылок не образует цикла исполнения. Предыдущий каталог не нужен.

## Независимые курсы

Курс публикует `reference-catalog.json` рядом со своим сайтом. Другой курс подключает
этот каталог по URL, локальному пути или `file:` URL:

```yaml
reference-catalog:
  namespace: java
  projects:
    book: {path: book, format: html}
  publication:
    title: Программирование на Java
  exports:
    book: [sec-types, sec-collections]
  imports:
    os:
      source: https://example.org/os/reference-catalog.json
      namespace: book
      base-url: https://example.org/os/
      title: Операционные системы
      style: external
```

`@os:sec-processes` адресует раздел внешнего курса. `namespace` выбирает
пространство имён внутри импортируемого каталога; `base-url` задаёт адрес его
публикации. `source` не привязан к размещению соседних репозиториев. Псевдонимы
импорта должны отличаться от пространств имён собственных проектов.

`exports` задаёт открытый интерфейс курса. `"*"` экспортирует все цели выбранного
локального пространства имён, список — только указанные ID. Пустой словарь
`exports: {}` и отсутствие поля дают пустой публичный каталог. Публикация целей
всегда требует явного выбора. Импортированные каталоги повторно не экспортируются. `publication.title`
и `imports.*.title` дают читателю название курса, а стиль `external` выделяет
ссылку на чужую публикацию. Доступны также стили `default`, `number` и `title`.

Поле `file` и версионные варианты каталога не поддерживаются. Используется
текущий контракт QRC; поле `schema: quarto-reference-catalog` в созданном JSON
обозначает тип документа, а не выбираемый номер версии.

## Проверки

Расширение проверяет наличие подпроектов, допустимые форматы, отсутствие пересечения исходников с выходным каталогом, уникальность целей, HTML-якоря, корректность штатных подписей и межпроектных ссылок. У объектов Revealjs должен существовать содержащий слайд с явным ID. Конфликт каталога слайдов с содержимым главной книги останавливает сборку.

Внутренние URL относительные, поэтому сайт переносим между локальным сервером, GitHub Pages под префиксом репозитория и отдельным доменом. Публикуется только итоговый каталог публикации.

Нормативная форма конфигурации описана в `publication.cue`. Фактические файлы, HTML-якоря и коллизии проверяются Reference Catalog. Эта схема не включается в `#Course`: её правила не относятся к оцениванию заданий.
