# Видимость и профили

Quarto владеет набором файлов, профилями, условным содержимым и форматами.
Core использует публичный `quarto.project.profile` для извлечения учебных
фактов в том же контексте. Краткие `.when-*`/`.unless-*` не поддерживаются.

```qmd
::: {.content-visible when-profile="full"}
Материал полного представления.
:::

[Материал профиля review]{.content-visible when-profile="review"}
```

Используйте штатные `.content-visible`/`.content-hidden` и
`when-profile`/`unless-profile`. Условие профиля применяется до извлечения
фактов. Скрытая ветвь всё равно проходит проверку авторских объявлений и ключей.
Core оценивает только компонент native условия профиля. Остальные условия
формата/метаданных остаются у Quarto; AND/invert сохраняется и для отдельной
публичной экспортной проекции.

## Аудитории

Для двух публикаций настройте `_quarto-student.yml` и `_quarto-full.yml`:

```yaml
# _quarto-student.yml
project:
  output-dir: _book-student
course:
  view: student
```

Full использует отдельный output-dir и `course.view: full`. Значение view
не должно противоречить активному профилю аудитории. Функциональные профили,
например `java`, `review`, остаются независимыми от student/full.
Без явной аудитории обычный native документ сохраняет авторские решения.

Student исключает `.grading-notes`, `.answer-spec`, отметки `.correct`
и закрытые решения задач книги. Решения примеров и демонстраций доступны,
если сама задача и её окружение видимы. Reveal оставляет авторские решения;
штатные `.fragment`, `.notes` и условное содержимое определяют их показ.
`course-role="control"` описывает назначение задачи и не скрывает её автоматически.

Полные контрольные страницы автор включает только в списки входных файлов full:
например, задаёт разные `book.chapters` в профилях. Нативный `resources`
и подготовительные hooks могут копировать файлы; отсутствие ссылки или главы
не является запретом на копирование. Проверяйте список фактических результатов.
Открытый Git содержит исходники независимо от профиля публикации.

## Ресурсы и экспорт

Публичный ресурсный отбор исключает исходные QMD, конфигурацию Quarto,
служебные каталоги, скрытые ресурсы и закрытые области проектов задач.
Разрешённые общие ресурсы не становятся закрытыми из-за использования в решении.
Проверяются существование, принадлежность корню и файловые алиасы.

Экспорт явно выбранной работы читает полные исходники выбранного банка,
включая control-страницы вне списков глав HTML для student/full. Публикационный
профиль не определяет состав выбранного экспорта. Условие и публичные поля
ответа отделяются от решения, ключа и grading-notes; потребитель публикует
только публичный пакет. См. [Body API](../docs/body-export.md).

При исходном экспорте audience-условие на целой задаче/работе и её внешних
контейнерах не исключает объект из выбора. Условия внутри задачи продолжают
отделять публичное условие от материала только для full. Функциональные профили
сохраняются. Это относится к служебному исходному проходу, а не к публикации HTML.
