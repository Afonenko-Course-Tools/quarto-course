# Видимость и профили

Quarto владеет файлами, профилями, условным содержимым и форматами. Core
использует публичный `quarto.project.profile` в том же native контексте.
Правила этой ветки внедряются по [принятому контракту](authoring-model-next.md).

## Публикация банковского условия

В объявленном `exercise-bank: true` эффективная `statementVisibility`
обязательна. Атрибут `statement-visibility="open|restricted"` задачи имеет
приоритет над `exercise-statement-visibility` в `_quarto.yml`/`_metadata.yml`.
Отсутствие обоих значений — ошибка. Проверяется текущая raw декларация,
без анализа Git, старых рендеров и истории публикаций.

| Задача банка | Student-сайт | Full-сайт |
| --- | --- | --- |
| open, обычная | Условие; решение скрыто | Условие и решение |
| open, demonstration, решение есть | Условие и решение | Условие и решение |
| restricted | Условие, решение и ссылка назначения скрыты | Условие и решение |

Только `course-role="demonstration"` открытой канонической задачи даёт доступ
к связанному решению. Stage назначения не переписывает role/visibility банка.
Роль control сама не скрывает текст. Нативный exm вне банка не даёт банковских прав.
Банковская политика действует и для student Reveal; обычные слайды вне банка
сохраняют нативные решения, notes и fragment.

До audience projection проверяются все raw объявления и ключи, включая
удаляемую restricted задачу. В student сохраняются только необходимые
канонические факты: ID/source, difficulty/time, statementVisibility,
purpose, hasSolution и hasPublicSolution; закрытые AST не сохраняются.
Student HTML, поиск, QRC, ресурсы и ZIP не должны содержать удалённые
условия или решения. Открытый Git остаётся отдельным опубликованным источником.

## Нативные профили

```yaml
# _quarto-student.yml
project:
  output-dir: _book-student
course:
  view: student
```

Full использует отдельный output-dir и `course.view: full`; view не должен
противоречить профилю аудитории. Функциональные java/review остаются независимыми.
Без аудитории обычный native документ сохраняет авторские решения.
Вне банка native exr/exm/sol не получают банковской приватности автоматически.

```qmd
::: {.content-visible when-profile="full"}
Дополнительный преподавательский материал.
:::
```

Используйте штатные `.content-visible/.content-hidden` и
`when-profile/unless-profile`; сокращений when-full/unless-student нет.
Условие профиля применяется до извлечения публичных фактов, но raw проверка
не пропускает скрытую ошибку. Core оценивает компонент условия профиля;
условия формата/метаданных и AND/invert остаются у Quarto.

Нативные resources/hooks могут копировать файлы. Отсутствие главы в меню,
ссылки или запись gitignore не ограничивает копирование. Не включайте исходные
QMD, закрытые пакеты и `_generated` в student ресурсы.
У student банковского HTML отключите встраивание исходника штатными
`code-tools: {source: false}` и `keep-source: false`; не добавляйте локальный
QMD в code-links. Обычная внешняя ссылка на открытый GitHub разрешена.
Проверяйте фактические source modal, HTML и копируемые файлы:
удалённый Core AST не редактирует оригинальный исходник для нативного Source.

## Выбранный экспорт участнику

Restricted ограничивает публикацию сайта, но разрешает выдачу выбранного
условия участнику Print/PrairieLearn. Вопрос Body несёт отдельную
`statementVisibility: open|restricted`. Его `visibility: public` означает
participant-safe часть выдачи, а не открытость условия на сайте.
Прежние guards ключей, решений, gradingNotes и ресурсов не ослабляются.
Moodle получает нужные преподавательские ключи по своему контракту.

Экспорт читает полные исходники native владельца выбранного book-проекта,
включая страницы вне HTML chapters. Только явно объявленные банковские задачи
входят в каноническую модель. Публикационный профиль не задаёт selected состав.
Audience-условие на целой задаче/работе или внешнем контейнере не исключает
её из исходного выбора. Условия внутри задачи продолжают отделять публичную
часть от full-only. Функциональные профили сохраняются.
Публичная ресурсная проекция исключает source, служебные файлы, скрытые
ресурсы и закрытые области проектов; разрешённый общий ресурс не становится
закрытым только потому, что используется в решении. См. [Body](../docs/body-export.md).
