# Семантика, представление и оформление курса

Репозиторий поставляет три отдельно включаемых расширения. Совместное
хранение упрощает выпуск согласованной версии; оно не делает тему обязательной
частью учебного формата. Во всех проектах остаются `html` и `revealjs`.

| Компонент | Ответственность | Не отвечает за |
|---|---|---|
| `course-core` | Профили, учебные роли, метаданные, отношения, модель и CUE, задания и занятия | Цвета, сворачивание, кнопки презентации |
| `course-presentation` | Подписи метаданных, раскрытие ответа в лекции/самостоятельной работе/печати | Граф адресов, адаптеры оценивания, бренд |
| `course-navigation` | Кнопки, разделы, обзор, история, поиск и индикатор прогресса Reveal | Учебную семантику, ответы, права публикации |
| `bsu-theme`, отдельный репозиторий | `_brand.yml`, SCSS, визуальные токены учебных блоков и навигации | JavaScript и Lua, новые авторские блоки, собственные форматы |
| Quarto Reference Catalog, отдельный репозиторий | Межпроектные ссылки, каталог, переход к скрытому целевому объекту | Тип деятельности, сложность, оформление |

## Порядок обработки

1. Core применяет отбор по профилю и отделяет закрытые `.grading-notes`.
2. Core проверяет видимые учебные объекты, связи и метаданные и записывает модель.
3. Presentation добавляет представление к уже отобранному содержимому.
4. Quarto сохраняет собственную нумерацию `exr-`, `sol-`, callout и crossref.
5. QRC устанавливает межпроектные адреса; браузер раскрывает предков цели ссылки.
6. Навигация управляет Reveal; SCSS темы БГУ меняет только внешний вид.

Контракт един для всех документов проекта: YAML не содержит номера схемы.
Cloud и PrairieLearn дополняют модель оцениваемых заданий; вопрос без `target`
остаётся учебным элементом. Версия пакета хранится только в штатном описании
расширения Quarto и не выбирает диалект документа или модели.

## Авторский интерфейс

Условие остаётся нативным `#exr-*`. `course-role` уточняет учебный смысл:
`demonstration`, `prediction`, `discussion`, `self-check`, `objectives`,
`prerequisites`, `reading`, `takeaway`, `limitation`, `misconception`,
`criteria`, `deliverables`. Определения, теоремы, примеры, колонки, вкладки,
диаграммы и аннотации к коду используют штатную разметку Quarto.

```qmd
:::: {#exr-boundary course-role="prediction" difficulty="introductory" time="2" work-mode="pair"}
## Совпадающие границы

::: {course-role="prerequisites"}
- Контракт функции: @sec-contract.
- Граничные значения: @book:sec-boundaries.
:::

Что вернёт `clamp(7, 3, 3)`? Обоснуйте прогноз.
::::

::: {#tip-boundary .callout-tip for="exr-boundary"}
## Подсказка
Сколько значений содержит диапазон?
:::

::: {#sol-boundary for="exr-boundary"}
## Объяснение
Результат — `3`: диапазон состоит из одного числа.
:::
```

`time` — авторская оценка в целых минутах, не таймер. Сложность:
`introductory`, `intermediate`, `advanced`; форма работы:
`individual`, `pair`, `group`. У блока чтения есть независимое
`requirement="required|recommended|optional"`.

Для страниц рефератов, которые участвуют в списках Quarto, значения можно
хранить один раз в YAML:

```yaml
difficulty: intermediate
work-mode: individual
course-pedagogy:
  document-defaults: true
```

Core применяет эти значения к упражнениям и видам деятельности документа;
локальные атрибуты имеют приоритет. Список использует то же поле `difficulty`.
Если оценка времени неизвестна, поле не требуется.

Предварительные знания — именованный логический блок со стандартными ссылками,
а не новый синтаксис адресации или автоматический граф допусков. Общие списки
переиспользуются через Quarto `include`. `for` связывает блок с видимым
упражнением того же документа; внутри упражнения владелец выводится из вложения.
Межпроектные материалы адресует QRC.

## Показ ответа и публикация

```yaml
filters: [course-core, course-presentation]
course-presentation:
  mode: lecture  # или study
  answers: auto  # или expanded
```

| Вывод | `lecture` | `study` |
|---|---|---|
| Reveal | Штатный фрагмент, раскрываемый переходом вперёд | Сворачиваемый блок по нажатию |
| HTML книги | Ответ открыт | Штатный сворачиваемый callout |
| Печать HTML / Reveal `?print-pdf` | Все опубликованные ответы открыты | Все опубликованные ответы открыты |
| PDF через небраузерный формат Quarto | Статическое полное содержимое | Статическое полное содержимое |

По умолчанию Reveal использует `lecture`, HTML — `study`. `answers: expanded`
делает опубликованные ответы открытыми независимо от режима. Формат и режим
не меняют `course.view`: печать не возвращает исключённые профилем элементы.
Закрытые критерии преподавателя остаются `.grading-notes`, публичные критерии
задания — `course-role="criteria"`.

Presentation отвечает за печатное раскрытие собственных ответов, обычных
callout/details и вкладок; navigation лишь открывает режим печати Reveal.
Кнопка PDF открывает страницу для браузерной команды «Печать → Сохранить как PDF»;
создание файла без диалога — отдельная автоматизация сборки. SCSS темы БГУ не задаёт
правила видимости ответов.

## Установка и независимое включение

`quarto add Afonenko-Course-Tools/quarto-course` устанавливает
пакеты локально. Навигация активируется через
`format.revealjs.revealjs-plugins: [course-navigation]`, представление через
`filters: [course-presentation]`. Установленный, но не подключённый UI не
меняет документ. Для полноценной проверки учебного контракта подключается Core.
Ни один UI-пакет не содержит `contract.json` адаптера оценки.

BSU подключается отдельным файлом настроек `_bsu.yml`: `brand`
указывает `_brand.yml`, `theme` дополняется `brand` и SCSS. В шаблоне
использованы локальные пути установленных пакетов `_extensions/bsu-theme/`; при установке из
GitHub Quarto может создать `_extensions/BSU-RFCT-Afonenko-Courses/bsu-theme/`. Используйте
фактический путь установленного пакета, который показывает `quarto list extensions`.
Настройки остаются в корне каждого независимого подпроекта, чтобы пути работали
и в сборочном снимке QRC.

В HTML основа — Cosmo, в Reveal — штатный `default`: Cosmo является темой
Bootstrap и не является темой Reveal. Удаление `_bsu.yml` из `metadata-files`
возвращает стандартный стиль, сохраняя семантику и управление.

Обновление — обычное `quarto add`/`quarto update` с последующим коммитом
установленных исходников. В CI нет загрузки «последней» темы. Submodules,
особый менеджер пакетов и `bsu-course-revealjs` не требуются.

## Границы учебного контракта

Ожидаемый и фактический результат шага, запуск кода, проверка ответа и таймер
не входят в это расширение. Cloud-контракт описывает свои предметные данные
самостоятельно.

## Установка и активация

Установка пакета не добавляет проектных обработчиков. Core включается фильтром;
обработчики проверки добавляются явно в `project.pre-render/post-render`.
Адаптеры выбираются через `course.adapters`, а их фильтры указываются отдельно.

Словарь ролей, атрибутов, перечислений и русских подписей находится в
`_extensions/course-core/contract-vocabulary.json`. Производные файлы CUE,
TypeScript и Presentation проверяются `node tools/sync-contract.mjs --check`.
Пакеты не зависят от исходников соседнего пакета при установке.

Скачивание и составная публикация выделены в самостоятельные расширения.
Обработчики Core не удаляют чужие каталоги и не создают архивы.
